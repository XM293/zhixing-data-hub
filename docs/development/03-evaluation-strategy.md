# 评测与验收策略

## 评测层级

### 组件测试

验证连接器、解析、实体映射、指标计算、记忆状态和工具Schema。

### 场景评测

验证制度问答、经营问数、角色风格、冲突处理、拒答和数字会议。

### 业务试点

验证员工是否减少重复询问、管理者是否节省时间、答案是否被采纳以及纠错成本是否可接受。

## 首期评测集

### 制度问答

- 100个高频真实问题。
- 每题标注适用制度、版本、关键证据和不可接受答案。
- 覆盖生效/废止冲突、跨部门权限、资料缺失和模糊问题。

### 经营问数

- 30个固定指标问题。
- 每题保存标准SQL或对账结果、时间范围、维度和允许误差。
- 覆盖GMV、退款率、广告ROI、库存周转和毛利。

### 经营诊断与简报

- 固定同一企业、范围、窗口和指标版本后，对事实数值、变化率、风险分级和证据引用做确定性校验。
- 模型只能组织推断与建议，不能改写指标事实；所有引用必须命中本次冻结的 `EvidenceSnapshot`。
- 覆盖模型正常、结构错误、超时和不可用四类路径；降级输出必须显式保存 `execution_mode` 与原因。
- 同一幂等键不得生成重复分析；同一业务日的多次有效分析必须形成递增简报版本并保留来源运行。
- 越权门店、员工发起分析和平台管理员冒用业务权限必须拒绝，读取简报仍按主体范围裁剪。

### 角色分身

- 30个需要管理判断的问题。
- 角色本人按“事实正确、思路相似、语气适合、边界清楚”评分。
- 风格评分不能抵消事实错误。

### 工具调用

- 每个工具覆盖正常、空结果、超时、参数错误、重复请求和权限拒绝。
- R2以上工具必须证明不会在未生成ActionProposal时产生外部状态变化。

### 身份与权限

- 覆盖匿名、会话失效、账号停用、跨企业、跨部门、跨店铺和仅本人范围。
- 覆盖菜单不可见后直接访问 URL、直接调用 API 和伪造客户端范围参数。
- 覆盖员工调用 CEO 分身、飞书未知身份、后台任务执行前权限撤销。
- 对相同 `ActorContext`，Web、API、Agent、MCP 和 Worker 必须得到一致授权结果。
- 授权拒绝必须包含稳定错误类型并产生可查询的决策记录，不向调用者暴露敏感策略细节。

## 首期门槛

- 制度回答引用覆盖率：100%。
- 已知问题事实正确率：不低于95%。
- 已废止制度被误当现行制度：0例。
- 指标对账准确率：不低于99%，舍入规则除外。
- 跨角色不应展示的信息泄漏：0例。
- 越权数据读取或未授权工具执行：0例。
- 权限撤销后继续执行外部写操作：0例。
- 无依据却给出确定性结论的比例：低于2%。
- 员工试点中重复咨询转人工比例持续下降，并保留原始基线。

## 结果记录

每次评测保存：代码版本、配置版本、模型、评测集版本、通过率、失败分类和回归对比。不得只保存一个总分。

## 当前运行器切片

- `evals/schema/evaluation-case.schema.json`、`evaluation-run.schema.json` 与 `evaluation-candidate.schema.json` 定义可移植合同。
- 数据库迁移 `0022_evaluation_runner` 保存版本化套件、案例、运行和逐项检查；`0023_feedback_evaluation_candidates` 保存人工纠错候选及其不可变审核结论。
- `/console/twins/evaluations` 提供固定案例、检查矩阵和历史基线对比。
- 人工纠错只能先成为待审核候选；具备 `evaluation.manage` 的负责人接纳后才能写入固定回归集。
- `m1-role-twin-smoke` v1 的 6 项案例只用于证明运行器；正式题量与上述首期门槛不因此下调。
- 空测试库未同步经营快照时不强制指标数量；指标评测集必须在固定数据快照或对账夹具就绪后单独运行。
