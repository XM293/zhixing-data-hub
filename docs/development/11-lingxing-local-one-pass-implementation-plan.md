## 1. 文档目的

本文把领星 ERP、集团多法人、数据同步运行时和数据中心管理台合并为一个可由单个 Codex 会话持续执行的本地工程任务。该任务完成后，生产接入只需要注入正式组织主数据、凭据引用和经脱敏确认的来源样例，不应再改变租户、同步、权限和页面主架构。

“一次性改造”是指一个任务内完成契约、迁移、后端、Worker、前端和测试的完整闭环，不是跳过阶段验证的大爆炸式重写。执行会话应在每个阶段通过针对性质量门后自动进入下一阶段，只有全部验收通过才把 `DAT-011` 从 `in_progress` 改为 `review`。

生产数据库清理、真实密钥注入、真实历史回填、服务器发布和飞书接入不属于本任务。它们必须在本地闭环通过后，按 [`10-lingxing-erp-real-data-and-group-rollout-plan.md`](10-lingxing-erp-real-data-and-group-rollout-plan.md) 单独执行。

## 2. 当前基线与根因

当前系统已有可复用底座：

- 集团、法人企业、业务单元、成员关系、范围声明、合并口径和来源映射表；
- 本地密码会话、企业切换、后端权限守卫、服务端菜单投影和审计；
- 数据来源、同步批次、Raw 记录、规范经营事实、指标、质量和数据中心页面；
- 通用后台任务、领取租约、重试、幂等键和一次性 Worker 执行令牌；
- 云 PostgreSQL、API、Worker、Web 和 HTTPS 生产运行基线。

尚未闭环的根因集中在以下能力：

1. W0–W3 仍缺少经过 Schema 约束的规范实体和经营事实写入；
2. 生产 bootstrap 只允许在 test/verify 库执行，尚未形成生产副本交接事务；
3. 店铺归属人工审核、来源资源详情和集团管理台仍需补齐完整页面闭环；
4. W4–W8 的官方只读资源 Schema、分页或异步报告协议尚未确认；
5. 真实凭据仍只支持受限环境引用，尚未进行真实账号探测和数据导入。

代码扫描中的演示常量包含合法的 seed、fixture 和测试引用。本任务只禁止它们出现在生产运行模块中，不应机械删除开发种子或测试样例。

## 4. 目标运行链路

```text
管理员创建来源
  -> 选择集团 / 法人 / 业务单元
  -> 保存 provider_key + credential_ref，不保存密钥
  -> 启用只读资源
  -> API 创建 SyncRun 和后台任务
  -> Worker 按资源 / 范围 / 分区 / 页执行
  -> RawPageManifest + 压缩原始页
  -> Staging 校验与 MappingConflict
  -> Canonical Entity / Fact 幂等写入
  -> 质量对账与资源 checkpoint
  -> Metric / Group Read Model
  -> 工作台 / AI / MCP / 会议 / 数字孪生读取同一 ScopeContext
```

同步过程中任何一页失败都不能删除上一批有效事实，也不能把父运行标记为成功。重试从最后确认的 checkpoint 继续，不重放已确认页的规范事实。

## 5. 验收场景

本地测试必须构造一个集团、两个法人企业和至少三个业务单元，使用完全合成且脱敏的领星响应 fixture：

1. 集团管理员登录后可切换集团、法人和项目范围；
2. 子公司负责人只能看到本企业及已授权业务单元；
3. 管理员为两个法人分别创建同一 `provider_key=lingxing` 的来源实例；
4. 凭据只保存为 `credential_ref`，API、日志、审计和页面均不返回秘密；
5. 提交 W0 同步后 API 立即返回排队运行，Worker 分页执行；
6. 运行中断后从 checkpoint 恢复，重复提交和重复页不会产生重复事实；
7. 未映射店铺进入冲突队列，批准后归属指定业务单元；
8. W1-W3 合成数据进入实体、订单、退款和库存事实；
9. 集团视图只聚合已授权企业，并返回参与企业、币种、口径版本和 `data_as_of`；
10. 另一企业的来源、Raw 清单、运行、映射和事实均无法越权读取；
11. 数据源、同步任务和映射页面使用真实 API，不读取组件内 fixture；
12. 关闭领星 Provider 后页面显示不可运行状态，不能伪装成功。

### P1：契约与数据库迁移

从 `0054` 开始按语义拆分迁移，不要求把所有变化塞进单个迁移文件。迁移必须兼容空库和由 `0053` 升级的现有库，采用新增列、回填、约束收紧三步法，避免破坏性重命名。

#### 1. 来源实例

扩展 `ExternalSystem`：

- `provider_key`；
- `business_unit_id`；
- `credential_ref`；
- `access_mode=read_only`；
- `capability_version`；
- `connection_status`、`last_probe_at`、`last_probe_error_code`；
- `version`、`created_at`、`updated_at`；
- 受控的官方 Host 配置，不允许生产来源任意输入 URL。

#### 2. 资源与运行

新增或等价实现：

- `SourceResource`：资源键、方法、路径、分页器、容量、窗口、Schema 版本、启停和权威角色；
- `SyncResourceRun`：父运行、资源、范围、分区、状态、计数、重试和官方请求 ID；
- `SyncCheckpoint`：资源与分区的页码、offset、时间水位或异步报告状态；
- `RawPageManifest`：存储键、内容哈希、压缩方式、字节数、行数和请求摘要；
- `MappingConflict`：外部对象、候选归属、冲突状态、审核人和版本；
- `SourceAuthorityRule`：事实族的权威、补充、对账资源和迟到窗口。

扩展 `SyncRun`，至少保存发起主体、`request_id`、`run_id`、后台任务、来源版本、Scope 快照、策略版本和父子运行汇总。

#### 3. 金额、时间与来源追溯

- 不直接删除现有 `*_fen` 字段；先增加明确币种与原币/本位币数值，再由兼容层维护旧接口；
- 使用能够表达 JPY、USD、EUR 等币种精度的十进制模型，不假设所有币种都有两位小数；
- 保存来源时间、UTC 时间、店铺时区和业务日期；
- 规范事实保存来源实例、资源键、外部主键、Schema 版本、映射版本、同步运行和 Raw 页哈希；
- 来源允许缺失的客户、地址、付款和物流字段保持可空，不生成伪值满足约束。

#### 4. 迁移验证

- 复制的 `0053` 测试库升级到 head；
- 既有 543 行平台数据不因迁移丢失；

### P3：领星只读 Provider

在现有自有连接器契约之下实现 `connectors/lingxing/`，不得让领星字段、ID 或错误码泄漏到上层页面和业务服务。

建议模块：

```text
connectors/lingxing/
├── auth.py
├── signing.py
├── client.py
├── errors.py
├── limiter.py
├── pagination.py
├── resource_catalog.py
├── redaction.py
├── connector.py
└── mapping/
```

必须实现：

- `CredentialProvider` 接口，只返回短生命周期凭据对象；生产配置只保存引用；
- Token 获取、刷新、过期前更新和刷新失败重新认证；
- GET、JSON POST、multipart 和异步报告的签名规范化；
- 固定时间、固定 nonce、中文、数组、嵌套 JSON、空值和 URL 编码测试向量；
- 按 `AppID + URL` 的资源级限流器；
- 429、业务限流、超时和 5xx 的有界指数退避；
- 认证、签名、白名单和无权限错误的永久失败分类；
- 日志、异常、审计和响应中的 Token、签名、AppID、AppSecret 与 PII 脱敏；
- 官方 HTTPS Host 白名单和只读资源白名单；
- `httpx.MockTransport` 或本地模拟服务契约测试，不访问真实领星账号。

### P4：W0-W8 资源包

本任务对“所有数据”的本地含义分两层，禁止把未知字段伪装为已完成映射：

| 波次 | 本地一次性交付 | 完成标准 |
|---|---|---|
| W0 授权与目录 | 资源定义、分页、Raw、市场/国家/店铺/多平台店铺规范映射 | 可形成待归属店铺目录 |
| W1 主数据 | 产品、SKU、品牌、分类、供应商、仓库、物流和账号目录的 Raw 与核心实体映射 | 外部键稳定且冲突可审核 |
| W2 交易与售后 | 订单、行、退款、退货、自发货的 Raw 与规范事实映射 | 金额、状态、数量和修改时间幂等 |
| W3 库存与履约 | 库存快照、库存流水、入出调拨与货件的 Raw 与规范事实映射 | 快照与流水可分区、可对账 |
| W4 采购与物流 | 全部确认只读资源进入版本化目录和通用 Raw 链路 | 未有可靠样例时标记 `schema_pending` |
| W5 广告与促销 | 全部确认只读资源进入目录、异步报告和 Raw 链路 | 归因窗口未确认时不生成集团指标 |
| W6 财务 | 全部确认只读资源进入目录和 Raw 链路 | 币种、结算期和汇率未确认时不映射利润真值 |
| W7 客服与体验 | 全部确认只读资源进入目录和 Raw 链路 | PII 与授权未确认时不上送 AI/MCP |
| W8 统计与源报表 | 全部确认只读资源进入目录和报告下载链路 | 只作为补充或对账，不重复计数 |

W0-W3 必须完成规范映射。W4-W8 必须完成资源目录、分页/报告状态和 Raw 接入框架；只有官方 Schema 与合成 fixture 足够明确的资源才实现 Staging/Core 映射。`schema_pending` 是明确状态，不是未完成提示文案，也不能进入指标、AI 或集团汇总。

### P5：API 入队与 Worker 执行

- `POST /sources/{source_key}/sync` 只校验权限、创建父运行并入队，立即返回 `queued`；
- 新增 `data-source.sync` 或等价后台任务类型；
- Worker 从任务中读取固定的企业、来源、资源和 Scope 快照，执行前重新校验来源状态；
- 外部网络请求必须发生在 Worker 执行链，不在用户 API 请求生命周期内；
- 每页采用“写 Raw -> 校验 -> 写规范数据 -> 更新 checkpoint”的事务边界；
- 任务租约失效、进程退出或网络失败后可恢复；
- 幂等键至少包含企业、来源、资源、分区、窗口和请求版本；
- 只重试可重试错误，永久错误进入资源运行失败和人工处理；
- 资源部分失败时父运行显示 `partial_failed`，不能覆盖上一批健康事实；
- 重跑、取消、停用来源和清理 Raw 都要求后端权限与审计。

Worker 可以复用模块化单体中的来源执行模块，但不能通过同步 HTTP 请求把整批执行重新塞回 API。若需要让 Worker 导入 API 领域包，应把可复用执行入口做成显式 workspace 依赖，禁止依赖临时 `PYTHONPATH` 或复制 ORM 定义。

### P6：Raw、Staging、Core 与对账

- 新增 `SOURCE_ARCHIVE_PATH` 和存储适配配置，本地测试使用临时目录；
- 原始页压缩、内容寻址、原子改名、路径穿越保护和哈希校验；
- 数据库只保存 manifest 与可搜索摘要，不在日志中输出完整请求/响应；
- Staging 校验输出接受、拒绝、警告和 Schema 漂移计数；
- 店铺、SKU、仓库、供应商和负责人先经映射再进入上层；
- `SourceAuthorityRule` 决定订单、退款、库存、广告和利润的唯一权威资源；
- 质量结果覆盖页计数、唯一键、金额、库存平衡、迟到更新和跨资源对账；
- Read Model 返回 `data_as_of`、参与来源、参与企业、币种和口径版本。

### 2026-09-11 官方响应容器修正

隔离候选的单页验证发现两个官方只读资源与自动抽取的行容器不一致。补货限制接口的官方字段表同时包含 `data.data` 月份信息和 `data.list` 记录列表，运行时行容器应为 `data.list`；Walmart Payment 可用报告接口的官方字段表声明顶层 `data` 为数组，运行时应先把该数组作为 Raw 行，后续映射再处理每项中的报告列表。候选证据只记录字段名与 JSON 类型，不保存响应值。

该差异通过版本化官方契约修正规则处理，并提升契约版本；不在 Worker 内按资源写临时分支，也不把错误响应当成零行成功。修正已固化到 `lingxing-contract-2026-09-11.7`，生成器仅在官方文档哈希未变化且字段结构断言仍成立时应用。旧资源版本先停排，待单页验证通过后再由契约迁移重新启用。

### 2026-09-11 NewAd 店铺范围资源接入决策

官方 NewAd 契约中有一组资源把 `sid` 与 `profile_id` 同时标为必填，但字段说明明确为二选一；
`sid` 直接引用亚马逊店铺目录，`profile_id` 只用于 VC 广告店铺。星云项目已经审核的是六个店铺
`sid`，因此 Amazon NewAd 资源统一按单个获批 `sid` 分区，显式省略 `profile_id`。不得把两个字段
同时发送，也不得从广告名称或账号名称推断店铺归属。

只纳入官方文档哈希已固定、响应行容器为 `data`、分页为 `offset/length`，并且请求字段包含
上述 `sid/profile_id` 二选一说明的只读资源。请求固定 `X-API-VERSION: 2`。带 `report_date`
的报表按单日回填和增量计划执行；其他枚举继续由版本化参数策略处理。只完成 Raw 的资源不进入
广告指标或集团汇总，真实接口无权限或不适用仍进入统一人工清单。

### 2026-09-11 来源依赖数组的执行边界

官方契约明确为数组、且数组元素可从当前来源与已审核范围的 Raw 依赖值逐项取得时，数组本身
不再作为人工 Schema 阻断。运行台账仍保存可比较的扁平分区参数，Provider 请求物化阶段才将
单个依赖值包装为官方数组；每个分区至少一个且不混合店铺，优先用单元素数组保证幂等、断点与
审计身份稳定。后续批量优化只能在保持同一范围和官方上限的前提下进行。

首个适用资源为 `getPrepDetails`：`sid` 使用已审核单店铺，`msku` 来自同店铺 Raw 依赖台账，
按官方 `array` 字段发送。缺少 MSKU 时计划进入等待，不使用合成值或空数组。响应继续 Raw-only；
预处理方式、标签方式等字段没有规范映射，不进入商品事实或指标。

官方表格还会把可选对象或可选数组内部的字段标为“必填”，其含义只在父筛选器出现时成立。
运行契约不得把这些子字段提升为顶层必填；当父筛选器未提供时整体省略。本规则仅适用于官方
父字段明确非必填的容器，不能用于跳过顶层必填数组。Walmart 回款明细的可选
`fieldCompares` 因此可省略，项目范围仍强制使用已审核的 `sids`。

### 2026-09-11 店铺标识命名空间修正

Amazon 店铺目录的来源键为 `store:{sid}`，多平台店铺目录的来源键为
`store:multiplatform:{store_id}`。两种数值 ID 不能因为字段名都含 `sid/storeId` 而互换。
动态资源必须声明 `amazon` 或 `multiplatform` 店铺命名空间；Worker、参数依赖和计划展开只
接受同命名空间的已审核绑定。当前人工批准的六家店铺来自 Amazon 店铺目录，因此不能用于
Walmart、TikTok、Temu、Lazada、Shein、Shopify 等多平台接口。

命名空间判定同时使用官方请求路径和官方文档目录。若接口路径是共用仓储前缀、但官方文档
明确位于 `MultiPlatform` 模块，仍按多平台店铺处理；不得仅凭 URL 路径缺少平台名而回退到
Amazon SID。

候选环境中过去用 Amazon SID 探测多平台接口得到的空结果或权限错误不是有效接口验收证据。
这些资源必须停用并退回“多平台店铺归属待审核”；既有 Raw 仅保留审计，不进入映射、指标或
完成率。获得多平台店铺外部 ID 的人工批准后，才允许重新单页探测。

### 2026-09-11 字符串数组依赖的单值分区

官方“查询已有商品信息”的 `skus` 最多 20 个，出单时段产品分析的 `sku` 最多 10 个；两者
都能由同一来源、同一获批 Amazon 店铺范围内的 Listing/MSKU Raw 依赖值产生。首期按一个
SKU/MSKU 一个不可变分区，在 HTTP 请求边界包装成单元素数组，避免批量重排改变幂等身份。
出单时段分析沿用官方说明中的 `sid/profile_id` 二选一规则：当前项目使用获批 `sid` 并省略
`profile_id`，`group_type` 按官方 `hourly`、`weekly` 穷举。没有真实依赖值时保持等待，不用
合成 SKU 发起真实请求。

### 2026-09-12 星云铁皮柜首期范围确认

业务范围已确认收窄为 Amazon-only：本期只使用名称包含“星云”的六家已批准 Amazon 店铺，
不抓取 Wayfair、Temu 或其他多平台店铺。官方目录仍保留 73 个多平台资源，以便目录完整性和
未来扩展，但它们在本期 rollout 中属于 `excluded_by_business_scope`，不建立多平台绑定、不排队、
不进入数据回填或完成率。由此，Temu 半托财务 403 与其他多平台探测结果不再是本期管理员协调项。

本期必须继续处理的是 Amazon 范围内 6 个仍需外部确认的接口/账号异常（另 2 个 FBA 新版报表异常已定位并完成候选侧店铺标识映射，商品预处理信息已通过财务 transaction 列表提供有效 MSKU 的关联链自行复测通过，FBC 已确认属于 Cdiscount 平台仓并按 Amazon-only 排除）、13 个仓库归属、1 个参数口径、
9 个上游依赖、14 个请求结构规则，以及历史边界和业务对账基线。116 个 Amazon/通用操作已自动判定为只读，
1 个写入操作已排除，不再形成只读语义人工阻断。
其中历史 `2001006` 已定位为 GET 数组参数线材化导致的签名不一致，连接器修复并在六家 Amazon 店铺隔离复测通过。
