## 1. 执行结论

领星连接条件已具备，服务器端认证和店铺只读探测已成功。当前不能立刻执行“清空后全量同步”，原因不是接口不通，而是现有代码仍有单演示企业硬编码，生产组织主数据尚不完整，且当前批次连接器不能安全承载数百店铺和多年度全域数据。

本轮正确顺序为：

```text
冻结生产基线
  -> 去除演示企业硬编码
  -> 完善集团/法人/项目上下文
  -> 建立领星 Provider 与资源目录
  -> 建立生产空库/租户引导和精确清理工具
  -> 同步外部目录并完成范围映射
  -> 分域历史回填
  -> 增量同步与对账
  -> 指标、AI、MCP、工作台和数字孪生切换真实 Read Model
```

不会把一次性拉取成功当成接入完成。每个数据域只有在“分页可恢复、幂等、映射、对账、权限、监控和 UI 空态/实态”同时通过后才进入生产。

“所有数据”按只读资源域交付，不调用任何业务写接口。

## 5. 连接器实现

### 5.1 模块边界

新增 `lingxing` Provider，建议目录：

```text
services/api/src/zhixing_api/connectors/lingxing/
├── auth.py
├── signing.py
├── client.py
├── resource_catalog.py
├── pagination.py
├── mapping/
└── connector.py
```

核心要求：

- AppSecret 仅由 CredentialProvider 读取；
- access token 只保存在 Worker 进程内，过期前刷新，刷新失败重新取 Token；
- 签名逐请求生成，参数规范化需要固定测试向量；
- GET、JSON POST、multipart 和异步报告分别实现；
- 同一个接口 URL 使用独立信号量，默认并发不超过官方令牌桶容量；
- 业务码 `3001008`、429、超时和 5xx 使用指数退避与抖动；
- 401/签名/白名单错误不可无限重试；
- 日志不得包含 Token、签名、AppID 全文、AppSecret、请求体中的 PII；
- 只允许资源目录登记的只读接口。

### 5.2 同步状态

新增或扩展：

- `SourceResource`：资源键、路径、方法、桶容量、分页器、窗口限制、Schema 版本、权威事实族；
- `SyncResourceRun`：资源/范围级开始、结束、读取、接受、拒绝、重试和请求 ID；
- `SyncCheckpoint`：店铺/仓库/广告账号等分区的 offset、页码、修改时间水位或报告任务状态；
- `RawPageManifest`：原始页路径、哈希、大小、行数、请求摘要和保留期限；
- `MappingConflict`：店铺、SKU、仓库或负责人无法映射时进入人工队列。

现有 `SyncRun` 保留为一次同步命令的父运行；现有 `SourceRecord` 用于需要逐条追溯的资源，不再强制所有大资源都逐行复制一份完整 JSON。

### 5.3 本地 Raw 存储

对象存储暂缓期间，使用：

```text
/var/lib/zhixing/source-archive/lingxing/<source-id>/<resource>/<yyyy>/<mm>/<dd>/
```

文件使用 gzip/zstd 压缩、内容哈希、原子改名和 root/服务用户受限权限。数据库保存 manifest，不保存凭据。首期设置容量告警和保留策略；历史完整归档的长期方案仍是对象存储或独立数据盘。

## 6. 规范模型修正

### 6.1 必须优先修正

- 所有同步和查询从 `ActorContext.enterprise_id`、任务声明或明确 Source ID 获取企业，不再导入 `seed.ENTERPRISE_ID`；
- `ExternalSystem` 增加项目归属和凭据引用；
- 订单、退款、广告、库存成本和财务事实增加 `currency_code`、原币金额、集团本位币金额与汇率版本；
- 时间增加 UTC、来源本地时间、店铺时区和业务日期；
- `store_key`、`warehouse_key`、`product_key`、`sku_key` 必须经过映射，不把领星数字 ID 直接暴露给上层；
- 允许来源缺失客户键、地址、省份或付款时间，不用伪造数据满足非空约束；
- 事实记录保存 `external_system_id`、资源键、源记录键、同步批次、Schema 版本和映射版本。

### 6.2 权威真值

为每个事实族登记：

- `authoritative_resource`：唯一权威来源；
- `supplemental_resources`：补充字段来源；
- `reconciliation_resources`：只用于对账的报表；
- `late_arrival_window`：迟到数据重扫窗口；
- `delete_semantics`：删除、隐藏、取消、作废和停止同步的区别；
- `freshness_slo`：允许延迟与预警阈值。

利润报表、订单报表和 Amazon 源报表不能各自生成一套 GMV 真值；集团层统一指标必须引用已经批准的权威资源和口径版本。

### 8.1 不采用直接清库

当前经营事实为空，最安全做法是先完成生产引导再退场演示租户。建议实现两个受控命令：

```text
zhixing-db production-bootstrap --manifest <file> --dry-run
zhixing-db demo-retire --backup-id <id> --dry-run
```

只有 dry-run 行数、外键影响、生产管理员登录和备份恢复校验通过后，才允许执行版本化 manifest。

### 8.2 保留、替换与删除

| 类别 | 处理 |

| Alembic 版本、权限定义、通用角色能力、字典类型、工具与 Skill 定义 | 保留或以生产 bootstrap 重建 |

清理前必须：

1. 创建新的数据库备份并完成可读取校验；

3. 生产集团、法人、项目和至少两个管理员账号已创建；
4. 新账号登录、菜单、权限、企业切换和审计通过；

交付：Token、刷新、签名、限流、错误分类、资源目录、店铺/市场/多平台店铺同步。

### R4：生产清理与 W0 映射

交付：正式备份、生产组织切换、演示数据退场、店铺到项目/范围映射。

### R5：W1-W3 真实同步

验收：同一问题在集团、子公司、项目和店铺范围返回正确集合与口径；证据可追溯到来源页和同步批次。

- 认证：Token 成功、失效 Secret、白名单错误、刷新重复使用、时钟偏差；
