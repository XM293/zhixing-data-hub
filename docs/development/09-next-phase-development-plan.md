# 知行数枢后续开发规划

版本：v1.1
基线：2026-09-08
适用范围：当前本地开发、生产服务器部署准备和后续客户进场

## 1. 规划结论

当前项目已经具备本地可运行的企业数据与智能体纵向切片，但还没有进入真实客户数据和真实渠道生产接入阶段。本规划把未完成工作分成三条轨道：

1. **本地闭环轨道**：现在继续完成，不依赖客户账号、客户字段或外部渠道凭证；
2. **生产预留轨道**：现在只完成契约、配置、权限、映射、回放和验收工具，真实端点放到生产服务器再接入；
3. **生产接入轨道**：必须等客户系统、云数据库、渠道凭证和实际字段确认后执行。

真实数据源和飞书机器人原属于第三条轨道。2026-09-08 起，首个领星 ERP 生产来源已具备服务器白名单、凭据和真实连通条件，因此真实数据源 P1 提前进入活动轨道；飞书仍保持生产预留。领星实施以 `docs/development/10-lingxing-erp-real-data-and-group-rollout-plan.md` 为准。

## 3. 本地闭环轨道

### L0：基线与文档收口

目标：让代码、任务、架构文档和产品验收状态使用同一套事实。

交付：

- 统一数字会议已迁移到 Runtime 的旧文档和任务描述；
- 给每个领域补充 `implementation / product_acceptance / production_readiness` 三维状态；
- 保留 `UIA-006` 产品人工验收门，不因代码已存在自动解锁领域任务；
- 为客户数据源和飞书建立“生产接入待办”，但不写入真实凭证。

退出条件：新人只读总账和本规划即可判断哪些能力已实现、哪些只是契约、哪些必须等生产条件。

### L1：Runtime 可靠性闭环

优先级最高，因为分身、会议、分析、客服和未来 Skill 都依赖它。

范围：

- Runtime Session/Turn/Event 的重启恢复；
- `waiting_approval` 的持久化恢复和人工恢复；
- 子进程退出、超时、取消和重复回放；
- Token、并发、执行时长和成本预算；
- 长任务 Worker 编排和租约恢复；
- Runtime 运行与 MCP 会话、Skill 版本、ScopeContext 的一致快照。

对应任务：`AGT-004`、`AGT-005`、`AGT-011`、`AGT-012`、`AGT-013`、`AGT-014`，以及 `OPS-004`、`OPS-005`。

退出条件：API 重启后可以安全识别运行状态；待审批任务不会丢失；重复恢复不会重复执行；失败能进入可解释的降级或人工恢复状态。

### L2：统一 AI 用例运行边界

把仍直接调用 `ResponsesAIProvider` 的经营分析、客服草稿、评测和自动巡店逐步包到统一 Runtime 用例接口内。迁移后仍可保留 Responses Provider 作为降级 Provider，但领域服务不再直接管理模型会话。

范围：

- 分析运行统一保存证据快照、Skill、工具白名单、模型、预算和降级原因；
- 客服生成与评测运行使用相同的 Runtime 运行记录；
- 自动巡店使用 Worker + Runtime + 当前权限重查；
- 所有输出继续保持结构化 Schema 和引用校验。

退出条件：Web 分身、数字会议、经营分析、客服和评测都能从同一套运行控制台追踪，但不要求所有场景立刻开放外部写入。

### L3：集团与子公司 Read Model

真实数据暂不接入，但先把多企业呈现和计算边界做完整。

范围：

- 集团、法人企业、业务单元、品牌、市场、店铺和仓库的树形 Read Model；
- 上下文切换后重新生成菜单、工作台、数字孪生节点和数据范围；
- 集团合并视图携带参与企业、数据截至时间、币种、汇率版本和抵消规则；
- AI、会议、MCP、Action 和数字孪生都保存同一份 ScopeContext 快照；
- 单企业安装自动投影为默认集团，保持现有行为兼容。

退出条件：使用模拟集团数据可以完整验证“集团总览 → 子公司 → 业务单元 → 店铺”的切换、权限隔离和合并口径，不依赖客户真实数据。

### L4：Action 与内部运营闭环

先完成不触碰第三方系统的真实内部闭环。

范围：

- R1 分析工具和 R2 草拟工具的注册、权限和审计；
- ActionProposal 的来源、证据、范围和职责分离；
- 执行前重新授权、乐观版本、幂等键、回读状态和人工恢复；
- 失败补偿、撤销、紧急停机和执行台账；
- 继续保持 `external_write=false`，直到生产阶段明确开放某个外部动作。

退出条件：内部工作项可以从分析、会议或客服草稿进入审批、承接、完成和复盘，且不会误调用第三方系统。

### L5：知识、记忆和评测治理

在没有真实 Provider 的情况下，先把平台自身真值和评测闭环做好。

范围：

- 知识原件、解析任务、切片、制度版本、权限过滤和引用定位；
- 聊天原件、候选记忆、审核、激活、退役和保留策略；
- 制度集、指标集、角色集、会议集和客服集黄金问题；
- Provider 对照统一记录 Recall@3、MRR、延迟、失败原因和端点指纹；
- 真实 Provider 缺失时保持禁用，不把沙箱结果写成生产能力。

退出条件：真实数据接入后只需要替换 Provider 和连接器配置，不需要重写知识、记忆、回答或权限领域。

### L6：数字孪生功能闭环和性能基线

数字孪生先服务于业务状态，不先做高精度装饰。

范围：

- 集团/子公司/业务单元/店铺/仓库/会议室对象键稳定；
- 数据质量、同步状态、会议状态、行动状态和告警映射为空间图层；
- 选中对象后进入对应二维中心或详情，不在 3D 内复制业务真值；
- 记录场景首屏时间、对象数量、帧率和切换耗时；
- 先用程序化几何和低复杂度人物验证大规模场景。

退出条件：数字孪生能够解释当前业务范围、数据状态和运行状态，并且在真实资产进入前已有性能基线。

## 4. 生产接入轨道（现在只预留，生产服务器再执行）

### P1：真实数据源接入

生产服务器满足数据库、网络白名单和客户账号条件后，按以下顺序实施：

1. 采集客户字段样例和接口文档；
2. 建立 `SourceSystem`、认证配置和范围映射；
3. 先接一个只读来源，完成全量、小范围增量和回放；
4. 对账订单、退款、库存、广告和客户主档；
5. 固化 `source_schema_version`、`mapping_version`、游标和失败语义；
6. 通过真实数据评测后，再开放更多事实族和历史回填。

首个生产连接器不得直接把源字段暴露给页面、Prompt、MCP 或数字孪生。

### P2：飞书机器人接入

生产服务器和飞书应用凭证准备好后，按以下顺序实施：

1. 配置 Webhook、签名校验、租户校验和事件回调；
2. 外部身份进入 `ChannelIdentity`，未知身份只进入绑定队列；
3. 复用 Web 分身同一 Runtime 用例、EvidenceSnapshot、Skill 和 ActorContext；
4. 先开放私聊问答，再开放群聊 `@`；
5. 加入消息幂等、限流、证据卡片、失败转人工和会话关闭；
6. 先只读问答，外部动作继续通过 Action 审批，不直接由机器人执行。

飞书接入验收必须包含：已绑定身份、未知身份、越权企业、越权店铺、重复事件、签名失败、模型失败和人工接管。

### P3：生产存储和数据库

客户正式部署前完成：

- 云 PostgreSQL 迁移、迁移预检和数据核对；
- 生产对象存储或客户服务器存储的保留策略；
- Redis 调度协调；
- 数据库、对象存储和密钥备份；
- 恢复演练、监控、告警和发布回滚；
- 生产环境禁止自动迁移、开发种子和契约沙箱。

## 5. 暂缓项

以下工作不作为当前主线：

- 真实外部写入和 Computer Use 店铺操作；
- 高精度 GLB、复杂骨骼人物和大规模 InstancedMesh；
- 在没有真实评测数据前确定 OpenViking、WeKnora、RAGFlow 的唯一供应商；
- 在没有真实聊天数据和容量指标前确定 TencentDB-Agent-Memory 或 Mem0 的唯一供应商；
- 为未来规模提前拆分微服务、引入 Kafka、湖仓或 Temporal；
- 继续增加只改变视觉、不增加业务状态的 3D 装饰。

## 6. 开发顺序和验收门

通用能力的原执行顺序保留；首个真实来源进入后改为两条并行主线：

```text
数据主线：L0 → 多企业硬编码清理 → 集团生产引导 → P1 领星 W0-W3 → P1 W4-W8 → 集团真实 Read Model
AI 主线：L1 Runtime → L2 AI 用例统一 → L4 Action → L5 知识/记忆/评测 → L6 数字孪生
共同出口：P2 飞书机器人 → P3 生产规模化
```

每个阶段必须同时满足：

- 代码和数据库迁移完成；
- 自动化测试和固定样例完成；
- 运行记录、权限、范围和错误语义可追溯；
- 文档更新并标记实现成熟度；
- 页面不使用解释性旁白掩盖缺失能力；
- 生产接入项没有凭证时保持禁用或明确的契约沙箱状态。

## 7. 当前建议的下一批任务

下一批优先完成真实数据接入前置与领星核心连接器，飞书仍暂缓：

1. 去除 API、Worker 和 Web 对演示企业/集团常量的运行时依赖；
2. 完成集团、法人、项目、成员、来源归属和 ScopeContext 管理闭环；
3. 实现领星认证、签名、资源目录、限流、分页和 checkpoint；
4. 实现生产 bootstrap、demo-retire dry-run 和恢复验证；
5. 先同步 W0 目录并完成店铺归属，再执行演示数据退场；
6. 分批上线主数据、订单/售后、库存/履约和财务/广告等资源；
7. 同步推进 Runtime、Action、知识/记忆和数字孪生业务图层；
8. 真实经营 Read Model 稳定后再接飞书机器人。

## 8. 完成定义

本规划中的“完成”必须明确是以下哪一种：

- **契约完成**：接口、Schema、适配器和测试存在；
- **本地闭环完成**：数据库、API、权限、页面、Worker 和测试全部贯通；
- **生产接入完成**：真实端点、真实凭证、真实数据或真实消息经过验收；
- **生产就绪**：容量、备份、监控、回滚、权限、人工责任和故障演练通过。

除非明确满足后两项，不得对外表述为“已接入生产”或“自动化已上线”。
