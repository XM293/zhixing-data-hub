## 运行方式

资源 Schema 升级必须显式提交当前目录版本：普通资源启用不会将历史 schema_pending 改成 confirmed；只有当前目录已确认且提供规范映射的资源，才允许管理员确认版本并写入审核事件。目录仍 pending 或客户端版本过期时拒绝。此入口用于后续离线重放，不直接更改旧 Raw 内容或自动重算既有事实。

全量覆盖核对（2026-09-10）：官方 `_sidebar.md` 审计得到 680 个文档、659 个操作，其中 470 个为已确认只读或待人工复核的只读候选。版本化官方操作注册表覆盖全部 470 个操作；36 个操作对应当前 39 个运行时资源，其余 434 个保持 metadata-only，不能进入 Provider allowlist。目录 `.22` 已为 W0–W3 和 W4–W8 五类核心数据提供严格映射，报告任务状态保持 Raw-only。逐项核对官方方法、路径、请求参数、账号权限、分页和字段后，才能把 metadata-only 操作提升为可执行资源；不能用注册表覆盖数代替真实采集、历史回填或 Schema 对账。

先保留现有业务库和演示数据。镜像采集使用显式 deferred 模式，采集水位按已持久化 Raw 页推进，规范映射使用独立任务与状态。新建 Web 批量导入和周期计划默认选择 deferred，周期计划仍默认暂停；旧请求和存量计划保持 inline。镜像页目录不是完整来源记录 ODS，当前不提供未审核 Raw 内容的普通页面查询。

独立映射失败后可以通过既有 Raw 重放重新执行。镜像页指向最近一次映射运行，旧运行及审计记录保留；执行中不允许对同一镜像页重复启动另一个映射。采集数不包含离线重放读取数，采集成功不能表示映射成功或全量覆盖完成。

# 参数化资源的持续计划（0068）

周期计划必须保存已经校验的 resource_parameters，并把它们纳入不可变计划身份和任务幂等输入。Listing 按单一 sid 与 is_delete=0/1 分计划；国家地区按 country_code、头程物流商按官方筛选组合分计划。修改参数须新建计划，避免水位、checkpoint 或审计继续沿用到另一分区。0068 对旧计划新增非空 JSON 字段并以空对象回填；API 与管理 Dialog 只展示目录声明的必填参数。已确认的时间窗口资源仍需各自的增量策略，不能用固定历史区间的 snapshot 冒充持续增量。

通用窗口现按目录分成 `updated_utc` 和 `source_window`。前者只用于官方更新时间字段已经确认的资源；后者只承诺形成持续 Raw 镜像，Schema、币种、业务日期或稳定外部键未确认时不会投影。计划界面只要求静态分区参数，日期由水位生成；API 与 Worker 共同拒绝缺失时区、超过一年、字段注入和不支持窗口的资源。首次回填仍按七天子批次推进，任何部分失败会保留上次水位并进入人工处理。
