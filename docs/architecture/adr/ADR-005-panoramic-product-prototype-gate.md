# ADR-005：在领域实现前增加产品全景原型验收门

- 状态：Amended by ADR-006
- 日期：2026-08-25
- 决策范围：M0 交付顺序

## 背景

> 2026-08-25 修订：产品负责人未接受纯静态全景原型。后续验收改为 ADR-006 定义的“数据库驱动产品验收切片”。本文保留的信息架构、角色故事和人工验收门继续有效；“不创建数据库表、不连接测试服务”的限制不再适用。

FND-001 至 FND-004 已经确定长期领域边界、技术栈和应用骨架。后续原计划直接进入公共契约、数据库、身份权限和管理者分身纵向切片。

该顺序有利于技术风险控制，但产品负责人只能在较晚阶段看到完整管理台、角色工作台和跨模块流程。如果整体信息架构、页面动线或产品重点不符合预期，已经实现的接口和页面会产生返工。

另一方面，如果为了提前看到效果而一次性实现全部数据库和业务后端，会把尚未验证的页面字段固化成领域模型，同样会增加返工。

## 决策

### 1. 增加产品全景原型阶段

在 `DOM-001` 及后续领域实现前增加 `UIA-001` 至 `UIA-006`。该阶段交付可运行、可点击、可切换角色、可串联关键流程的产品全景原型，由产品负责人完成正式验收。

全景原型是应用骨架之后的产品验收门，不替代 M0、M1、M2 的真实实现，也不改变 ADR-001 至 ADR-004 的领域所有权和技术方向。

### 2. 原型覆盖最终产品全景但控制页面深度

原型覆盖：

- CEO、部门经理、员工和平台管理员工作台；
- 企业数据、知识、分身、会议、分析、行动和平台管理中心；
- 客服工作台作为 M4 应用预览；
- 身份、授权菜单、证据、版本、任务和审计等跨模块体验。

每个中心先实现代表性列表、详情和关键操作状态，不提前完成所有低价值 CRUD 页面。

### 3. 使用确定性的模拟数据和模拟接口

页面不得把演示数据直接散落在组件中。原型建立版本化 UI Read Model、统一 Fixture、模拟查询与模拟命令层。同一员工、店铺、指标、制度、分身、会议和行动在所有页面使用相同稳定 ID 和固定业务时间。

模拟接口可以演示状态变化，但必须在界面中持续标识“演示数据”。不得把模拟成功、模拟同步或模拟 AI 输出展示为已实现的生产能力。

### 4. UI Read Model 不等于领域模型

原型阶段定义两类结构：

1. 概念引用：来自已接受 ADR 的稳定概念和边界。
2. UI Read Model：为列表、详情、看板和流程展示组合的数据。

UI Read Model 不直接生成数据库表，也不成为领域真值。产品验收后，`DOM-*` 任务定义领域契约；真实 API 通过应用用例或投影层生成 UI Read Model。

### 5. 先验收跨模块故事，不只验收静态页面

原型至少串联以下故事：

1. 管理员配置组织、用户和访问范围。
2. 制度负责人导入并发布新制度版本。
3. 管理者创建分身并审核记忆候选。
4. 员工向 CEO 分身提问并展开引用证据。
5. CEO 查看店铺异常、发起数字会议并确认决策包。
6. 负责人审核行动提议并查看模拟执行记录。
7. 客服结合订单上下文生成回复草稿并转人工。

### 6. UIA-006 是人工产品验收门

`UIA-006` 只有在产品负责人确认以下内容后才能标记 `done`：

- 产品导航和中心划分；
- 四类内部角色的首页和常用动线；
- 各模块代表性页面和状态；
- 关键字段、术语、证据与版本展示；
- 跨模块故事和优先级；
- 明确记录保留、修改和删除的意见。

`DOM-001` 依赖 `UIA-006`。基础设施、日志和 CI 可以与原型并行，但不得绕过验收门进入领域实现。

## 原型质量要求

- 第一屏是实际工作台，不是产品营销落地页。
- 桌面端以高频运营工作为主，移动端覆盖浏览、问答和审批。
- 页面必须包含加载、空数据、错误、无权限和部分数据状态。
- 菜单和角色切换在演示模式中可用，但不声称已实现真实认证。
- 所有模拟 AI 结论显示证据、数据时间或明确的演示标识。
- Playwright 验收覆盖桌面、移动、关键故事和控制台错误。

## 不变内容

以下既有决策继续有效：

- 经营事实、正式知识、角色记忆和运行记录分离；
- 模块化单体优先；
- `AccessRole`、岗位和 `RoleTwin` 分离；
- Agent、MCP 和 Action 服从 ActorContext、证据和审批；
- 首个真实纵向切片仍是管理者分身；
- 数据中心仍从一个业务单元和一条真实数据链路开始。

## 影响

- README 当前阶段改为“产品全景原型验收”。
- 新增 `experience-blueprint` Epic 和 `UIA-*` 任务。
- `DOM-001` 从 `ready` 改为 `blocked`，依赖 `UIA-006`。
- 管理台原型使用可替换数据源，后续真实 API 不要求重写页面结构。
- 产品验收意见进入版本化报告，不以聊天中的零散意见作为唯一依据。
