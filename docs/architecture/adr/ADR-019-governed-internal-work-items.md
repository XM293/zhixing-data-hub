# ADR-019：受治理的企业内部工作项

- 日期：2026-08-30
- 状态：accepted
- 关联迁移：`0035_operational_work_items`

## 背景

数字会议和客户运营方案已经能够把模型建议送入职责分离审批，但批准后只有一条 `external_write=false` 的执行登记，员工无法领取、推进或提交结果。经营诊断也会生成可执行建议；如果分析、会议和客户模块各自建立任务表，会形成多套状态、权限和审计真值。

## 决策

1. `ActionProposal` 增加显式的 `business-analysis` 来源和分析运行关联。建议按 `analysis_run_id + source_action_index` 唯一，相同请求幂等返回，改变已提交建议的截止要求返回冲突。
2. 批准提案时继续创建 `ActionExecution(external_write=false)`，同时创建一条 `ActionWorkItem`。批准只表示可以在企业内部承接，不授权任何第三方写操作。
3. 工作项状态固定为 `ready`、`claimed`、`in_progress`、`blocked` 和 `completed`。释放回到 `ready`，重开回到 `in_progress`；每次转换必须带预期版本和幂等键。
4. `ActionWorkEvent` 追加保存执行主体、Actor 快照、转换、说明、结果证据和幂等键，不更新或删除历史事件。
5. `action.work.read/update/manage` 与原提案权限分离。员工只能读取授权范围并更新本人领取的工作；运营负责人可管理授权范围；CEO 和财务默认只读。
6. 列表、详情和转换都使用服务端 `ActorContext`、企业边界与范围授权。页面的角色切换和按钮隐藏只是权限投影。

## 后果

- 经营分析、客户运营和数字会议共享同一“建议 -> 审批 -> 内部工作 -> 结果证据”闭环。
- 员工获得稳定的运营工作台，管理者可以从追加式事件审计工作由谁、何时、以什么结果完成。
- 乐观版本避免两个处理人覆盖状态，幂等键避免网络重试生成重复事件。
- 当前不包含飞书任务、外部工单、店铺操作或 CRM/ERP 写回。生产写操作仍需独立实现工具授权、审批后复核、失败补偿和外部幂等。
- 本纵向切片不提前关闭正式 `ACT-001`、`ACT-002` 或 `ACT-005`。
