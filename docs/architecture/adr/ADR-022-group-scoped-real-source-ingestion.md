# ADR-022：集团范围内的真实来源接入与分层同步

- 状态：accepted
- 日期：2026-09-08
- 决策范围：集团/子公司、来源实例、真实 ERP 接入、同步运行与经营事实

## 背景

知行数枢已经存在 `EnterpriseGroup`、`Enterprise`、`BusinessUnit`、`ExternalSystem`、`SourceBinding`、`DataScopeMapping`、原始记录、同步批次和规范经营事实，但当前实现仍以单一演示企业为默认：同步服务固定使用演示企业常量，连接器注册表只支持测试来源，批次契约会一次性装载全部记录。

首个生产来源确定为领星 ERP。“星云铁皮柜”是集团某个子公司下的业务项目，不是已经确认的法人名称。领星账号当前可读取数百家跨国家店铺，也提供订单、库存、采购、物流、广告、财务、客服和多平台数据。直接把账号视为一个扁平企业，或把所有接口结果写进同一张通用表，会破坏法人隔离、项目归属、集团口径和后续多来源扩展。

## 决策

### 工作台范围兼容（2026-09-09）

工作台返回完整 ScopeContext v2。只有当前法人全域且主体具有法人全域授权时复用旧 overview；项目、店铺或集团选择不再读取旧全法人指标、活动、会议/行动列表与场景投影。工作台同时接入独立权威订单汇总组件，由已有规范查询按当前范围读取。旧数据域未完成范围查询前返回空集合，不将当前法人数据冒充所选集团/项目的数据。Web 按 scope_version 重建查询组件，防止旧响应在切换范围后回填。

### Raw 重放（2026-09-09）

重放是同一来源、单个 JSON Raw manifest 的受控队列任务，要求 source.manage、内容哈希与当前映射版本确认。API 不读取归档、不请求外部网络；Worker 重验账号权限、来源启用状态、归档路径/哈希/大小和页结构。复用同步运行、租约、取消和部分失败汇总，每次命令有独立 replay 分区，不推进外部采集 checkpoint。新运行的 manifest 复用内容寻址文件并保留原 fetched_at，规范映射的 observed_at 也使用原采集时间；不能把重放当作新数据采集来覆盖较新的事实。二进制报告或无规范映射资源拒绝重放到 Core；旧数据保持不变，错误进入既有 Staging/冲突链路。

### 权威订单汇总查询契约（2026-09-09）

工具层新增独立 R0 `query_authoritative_orders`，输入仅接受业务日期，不允许模型传入法人集合扩大范围；输出直接复用 `canonical-orders-v1`。通过已有工具目录、权限、MCP allowlist 和调用审计执行。Bootstrap v2 允许显式选择已审阅的只读工具模板，默认不登记；模板仅创建工具定义，不导入演示知识、记忆或经营事实，也不提升管理员以外主体权限。未知模板、重复模板和旧版本携带模板必须拒绝。

会议创建、决策确认、Action 审批和工作事件增加服务端重建的 `scope_context` 快照，保留既有 Actor 字段与 workspace 字段。同一审批创建的工作事件复用同一范围快照；旧 JSON 保持可读，不回填伪造的历史授权。范围快照只用于追溯，不能代替执行时权限校验。

新增独立的 `canonical-orders-v1` 只读汇总，统计业务日期闭开区间内、当前获权法人/项目/店铺中的权威订单记录数和按原币分组的订单金额。包含所有订单状态，不称为付款、GMV 或收入；同时返回状态计数、金额缺失数、来源/资源/Schema/映射版本分组及可继续查询 Raw 的血缘。源停用、资源未确认、权威规则停用立即排除。集团结果只汇总选中且获权的法人，不执行内部交易抵销，不能称为财务合并。没有已确认汇率契约时，本位币金额为空，不混加不同币种；空结果与完整覆盖不能等同。查询使用当前有效事实，`data_as_of` 是实际最大观测时间，不声称支持历史快照重建。使用数据库分组聚合，避免读取全部订单到应用内存。

### 售后事实的保真边界（2026-09-09）

官方售后父 id 明确非唯一，现行子 item_identifier 才能用于幂等映射；旧 md5 字段不作降级键。建立独立售后事实，分别保留退款、退货、换货数量与状态，以及来源金额文本、金额数值、币种、来源时间、UTC 和 Raw 血缘。货币符号不推断为 ISO 币种；不明确的格式、时区及夏令时歧义保留质量标志，禁止进入金额指标。全部子项先校验，再更新有效事实；坏记录或较早更新时间不得覆盖旧事实。人工批准店铺归属是进入法人/项目事实的前提，未确认的时间不假定为 UTC。

### 历史导入与持续采集（2026-09-09 补充）

- 当前单资源队列没有多资源历史规划或周期触发器。复用已有 `SyncRun.parent_run_id` 建立父批次，每个资源/UTC 时间窗口生成一个子运行和独立后台任务；父子与任务在一个数据库事务内入队。窗口最多 7 天，单批最多 128 个分区，超出明确拒绝，不截断。
- 首个可确认的增量策略是订单 `date_type=3`（UTC 更新时间）。历史窗口允许相邻边界重复，依靠来源外部键及更新时间幂等；周期增量保留重叠窗口和可配置安全延迟。只有全部子运行成功才推进调度水位；部分失败、撤权、取消均保留旧水位并转为待处理。每日额外回看窗口覆盖迟到变更。来源侧未更新的旧记录无法靠轮询检测，须重跑历史分区对账。
- 目录与当前库存支持定期快照；来源本地日期语义、增量字段或游标尚未确认的资源不推定为实时增量。异步报告任务查询由任务重试调度，不创建报告或重复订阅。
- 周期计划默认暂停，保存可信发起人及范围快照；显式启用后由 Worker 数据库轮询领取，每次入队及每页均重新核验权限。多个 Worker 使用行锁和同事务活动批次标记防重；不通过用户 HTTP 请求拉取外部数据，不依赖 Codex 定时任务。
- W0 官方“概念店铺”与“多平台店铺”分别使用 concept id 和 store_id，不能当作 Amazon sid 混用。汇率月表未明确本位币及换算方向，仅保留来源参考值，不能推定用于金额换算。
- 市场、国家地区及概念店铺作为法人内的规范参考目录保存来源血缘，不视为经营店铺或自动分配给项目。多平台店铺使用 `multiplatform:{store_id}` 来源命名空间，进入未分配店铺队列，Amazon sid 仅作为来源关联属性。月汇率资源保持 schema_pending，禁止进入金额换算；W0 并非所有资源均可直接进入经营事实，验收按已确认映射与明确阻断分别判断。

### 1. 组织与数据隔离

- `EnterpriseGroup` 表示集团治理和合并范围，不作为经营事实的租户键；
- `Enterprise` 始终表示法人企业，并继续作为数据、权限和运行的基础隔离键；
- `BusinessUnit` 表示法人下的事业部、品牌、项目或区域经营单元；“星云铁皮柜”首期登记为 `project` 类型业务单元；
- 店铺、仓库、品牌、SKU 和渠道使用稳定平台键，并通过 `SourceBinding`、`DataScopeMapping` 映射领星外部键；
- 集团查询显式展开为当前主体获权的企业集合，不通过伪造一个集团 `enterprise_id` 实现。

### 2. 来源实例

`ExternalSystem` 继续作为进入事实层的来源实例，不新建并行的第二套来源真值。新增或补齐：

- 所属法人企业和可选业务单元；
- `provider_key=lingxing` 与只读能力模式；
- 凭据引用、连接状态、最后探测时间和能力清单版本；
- 资源目录、同步策略和启停状态；
- 生产来源不能使用任意 Base URL，领星 Provider 只允许官方 HTTPS 主机。

数据库只保存凭据引用，不保存 AppSecret、文档密钥、access token 或 refresh token。当前私有化部署使用 root-only 文件凭据 Provider；后续可以切换 KMS/Vault，而不修改连接器契约。

### 3. 分页流式同步

新增资源级同步契约，替代“大批次一次性装入内存”的生产路径：

```text
SourceSystem
  -> SourceResource
  -> SyncRun
  -> SyncResourceRun
  -> SyncCheckpoint
  -> RawPageManifest
  -> Staging Mapping
  -> Canonical Entity / Fact
  -> Metric / Read Model
```

- 每次只读取一个资源、一个范围和一页；
- 每页写入、对账和 checkpoint 在同一事务边界内确认；
- checkpoint 由连接器拥有，平台不猜测 offset、页码或时间水位语义；
- API 只创建同步命令，Worker 执行实际网络读取；
- 重试只重放失败页，不重复提交已经确认的规范事实；
- 每个资源记录官方 request ID、Schema 版本、映射版本、请求参数摘要、页内容哈希和计数，不记录签名或 Token。

### 4. Raw、Staging、Core、Mart

- Raw：保存压缩后的原始页和元数据，当前使用服务器本地受控目录；
- Staging：按领星资源版本展开字段、状态和自然键；
- Core：保存稳定店铺、商品、SKU、仓库、供应商、订单、库存、采购、物流、广告和财务事实；
- Mart：生成集团、子公司、项目、店铺和岗位工作台所需指标与聚合。

本地文件存储只是当前部署选择，不改变 `ObjectStorage` 抽象。容量达到阈值或需要多节点时再迁移到对象存储。

### 5. 数据真值与“全部数据”

“对接领星所有数据”定义为：建立全部可用只读业务资源的目录和同步能力，并按优先级逐域上线。它不表示：

- 调用创建、修改、删除、发货、调价、库存调整等写接口；
- 把多个语义重叠的订单、利润和源报表同时当作权威真值；
- 把 ERP 用户自动创建为知行数枢登录账号；
- 把客户地址、电话、邮箱或员工登录 IP 暴露给 AI、MCP 或普通页面；
- 一次请求拉完全部历史数据。

每个规范事实族必须指定唯一权威资源、补充资源和冲突处理规则。写接口继续保持禁用，未来只能经 Tool Registry、Action 审批、当前权限重查、外部幂等和结果回读单独开放。

### 6. 金额与时间

- 保留原币金额与 ISO 币种；
- 集团聚合额外保存本位币金额、汇率版本和换算时间；
- 不把 JPY、USD、EUR 等金额直接写入名为“分”的单一口径；
- 时间统一保存 UTC，同时保留来源时间、店铺时区和业务日期；
- 集团指标必须返回参与企业、数据截至时间、币种、汇率版本和抵消规则。

### 7. 集团上下文

`ScopeContext` 扩展为以下显式选择：

```text
group_id
selected_enterprise_ids[]
business_unit_ids[]
store_ids[]
warehouse_ids[]
base_currency
consolidation_profile_version
data_as_of
```

本地实现以 0054 来源台账、0055 运行/范围元数据和 0056 币种/来源时间迁移承载资源级运行、页清单、断点、冲突、范围快照和原币追溯；PostgreSQL 约束在本地实例可用后复核，SQLite 回放保持兼容。

Actor、Runtime、MCP、会议、Action、工作台和数字孪生必须保存或引用同一范围快照。切换集团/子公司/项目后重新投影菜单和数据，不修改用户权限本身。

## 后果

### 2026-09-09 初始化与退役的身份保护

组织初始化 v1 只创建集团、法人和业务单元，不能表示正式管理员已就绪。新增严格 v2 manifest，显式列出角色模板、权限键及至少两名管理员的成员范围。只复用全局权限定义，不复制演示角色、账号、知识或会话；密码仅引用运行环境变量，预检不读取其值，执行不返回其值或摘要。初始化使用现有账号与权限模型，完成后必须经过真实密码校验、Actor 解析和范围授权测试。

预检列出每张身份与组织表的实际新增/已有计数并签出计划哈希。执行在领域入口再次校验 test/verify 数据库、显式确认、备份 ID 和计划哈希，串行化事务内重新核对身份及计数漂移；重复执行只复用匹配记录，不重置密码、不恢复被撤销的授权。退役保护身份关系、角色权限与范围授权表，保留基础用户意味着保留这些关系，而非仅保留 user_accounts 行。本任务不放开生产库执行门禁。

### 2026-09-09 规范映射修正：订单总额与付款事实

官方订单列表只承诺订单总额、币种、下单时间和订单状态；现有 `CommerceOrderFact` 则要求付款、成本、折扣、省份等非空字段，且旧经营接口按人民币分汇总。把缺失字段填零或把订单总额写为实收会制造事实。增加 `canonical_sales_orders` / `canonical_sales_order_lines` 承载销售订单，`canonical_inventory_balances` 承载实际库存平衡；现有付款和经营快照表继续表示原有契约，领星订单不重复写入这些表。查询契约分别命名订单金额、已付款金额和库存数量，只有明确权威来源、批准归属和币种口径才聚合。

主数据复用 `BusinessEntity`，通过 `canonical_entity_origins` 记录来源外部键、归属状态和 Raw 血缘。上述实体与事实使用同一 ORM 和映射入口；API 包改为可安装 workspace 包，Worker 显式依赖它，只导入领域模块、不导入 ASGI 入口、不回调 API。每页 manifest、Staging 校验结果、规范 upsert、冲突和 checkpoint 在同一数据库事务提交。金额使用 Decimal / NUMERIC，缺少币种或汇率时不生成本位币金额；快照时间与来源更新时间分开，迟到版本不覆盖较新的事实。

官方证据：[店铺](https://apidoc.lingxing.com/#/docs/BasicData/SellerLists)、[产品](https://apidoc.lingxing.com/#/docs/Product/ProductLists)、[订单](https://apidoc.lingxing.com/#/docs/Sale/Orderlists)、[库存](https://apidoc.lingxing.com/#/docs/Warehouse/InventoryDetails)。库存成本响应未确认币种，只映射数量，成本保持待确认。

### 2026-09-09 范围选择与治理执行约束

单店铺/仓库授权不能因缺少独立业务单元授权而失去自身数据，也不能通过补齐业务单元 ID 获得同项目其他店铺。ScopeContext 从已批准的来源实体血缘派生其所属业务单元，仅用于范围求交，原始店铺/仓库授权仍逐对象检查。已知来源实体不得通过旧提供者键的兼容回退绕过业务单元拒绝；无法定位项目的旧键遇到业务单元拒绝时失败关闭。

权威来源修正：旧 `SourceAuthorityRule` 只记录法人和资源名，不能区分同名资源的多个来源实例及不同项目。新增项目级 `SourceAuthorityAssignment`，以法人、业务单元、事实族唯一，显式绑定来源实例和已确认映射资源，使用乐观版本及审计。旧记录原样保留作为历史配置，不自动猜测来源或项目，也不进入规范事实统计。规范事实列表可以展示全部血缘；权威统计必须另外与有效归属、来源状态和权威指派求交集。每个项目独立选择权威来源，不按最近同步或记录数量自动选择。

浏览器验收修正：bootstrap 的管理员登录名支持邮箱形式，而历史登录接口仅接受字母数字及点线，导致正式初始化账号不能通过 Web 登录。初始化、账号创建、开发登录和密码登录改用同一登录名契约：去除首尾空白、casefold、禁止内部空白，长度 1–120。数据库精确匹配及同名歧义处理保持不变，不以演示法人定位账号。

冲突审核修正：批准不能等价于忽略校验错误。失败记录只能由后续同来源、资源和对象的有效映射写入“已验证修复”的 Raw manifest 证据，再允许人工批准；缺少证据返回 409。拒绝只记录审核决定，不释放事实进入指标。新失败清除旧修复证据并重新进入待处理状态，保留原审核人和时间。币种、时区待确认状态必须实际解决后才能通过此门禁。

治理范围修正：`allowed_enterprise_ids` 表示可以在该法人内读取获权子集，不能据此授予整个法人的组织修改权限。组织、成员和法人级治理必须另外取得显式法人或集团治理范围；仅获权业务单元、店铺、仓库的主体不进入组织治理。治理概览只列举具有完整法人治理授权的法人及其成员，避免把局部数据权限扩大为组织目录管理权限。唯一键冲突在 flush 和 commit 两个阶段统一转换为 409。

ScopeContext v2 的用户选择保存在 AuthSession 的受信字段，切换接口先与有效成员关系、角色范围及显式拒绝求交集，再写入会话。空授权集合不是“全部”。集团治理使用现有身份管理权限并独立检查集团范围；仅有法人权限不能更改集团或新建其他法人。业务单元禁止跨法人父子关系和循环，编辑校验版本；成员关系变更不隐式复制或提升角色权限。来源归属审核验证当前法人业务实体，已有规范事实的维度跨项目重分配必须单独迁移。

通用范围守卫的失败测试还证明：当前法人 allow 原先会匹配任意被请求的法人 ID。企业级通配只适用于该法人内部资源；请求另一个法人时必须精确匹配该法人授权，不能由当前法人授权隐式放大。

Runtime 契约增加可选 ScopeContext v2 快照，保持旧调用兼容，拒绝快照法人和 Actor 法人不一致。会议与分身 Runtime 调用填充并持久化快照；此快照用于追溯，不授予权限，工具执行仍依赖 MCP 当前身份再授权。

恢复已有 Runtime 线程之前必须比较当前与保存的法人和 scope_version。范围或权限版本改变时，旧线程可能仍含原范围上下文，故返回 409 runtime.scope_changed，要求新会话；缺少 v2 快照的历史记录保留可读但不能直接续问。不能只更新 MCP 权限后继续复用旧线程。

签发与调用时重新验证保存的 scope_selection，项目、店铺、仓库级会话去掉企业级 allow，仅保留选中维度及其允许的子资源，并保留 deny。旧会话没有选择信息时继续按原有约束再授权。集团汇总工具尚未完成，不能把传递选择信息等同于集团指标可用。

失败回归证明：MCP 会话按登录名重新解析会丢失签发时的当前法人，企业范围约束还会丢弃店铺级显式拒绝。会话再授权必须用持久化的账号 ID 和法人 ID，重新检查当前成员关系与权限；约束只能收窄，必须保留当前身份的全部 deny。本修正不代表 Runtime/MCP 的完整 ScopeContext v2 快照兼容已经完成。

### 2026-09-11 NewAd 的 `sid/profile_id` 二选一范围

NewAd 的 Amazon 广告资源由官方请求说明确认 `sid` 与 `profile_id` 二选一。当前项目已有人工批准的
Amazon 店铺 `sid`，没有独立批准 VC 广告账号，因此 Raw 采集只允许按单一 `sid` 分区并省略
`profile_id`。这使归档前后的范围校验都能复用现有店铺边界，也避免把账号级广告数据跨项目归档。

进入动态目录还要求官方文档哈希匹配、只读审查固定、响应 `data` 行容器及 offset/length 分页均已
确认。所有请求固定版本头 2；按日报表使用单日窗口。广告归因、预算币种和报表指标口径没有因此
自动获得确认，相关 Raw 不得直接成为权威广告指标。

### 2026-09-11 依赖数组保持单范围分区

只读接口的必填数组如果由已归档的来源标识组成，采用“台账标量、请求数组”的两阶段表示。
调度与回填按单个依赖标识形成幂等分区，Provider 在签名之前按官方字段类型包装为单元素数组；
数组不得跨店铺、法人或业务单元合并。这样既保留官方 JSON 请求形状，也不把任意客户端数组
带入计划身份或绕过范围授权。

该规则只适用于官方字段类型、元素来源和范围都已确认的数组。对象数组、多个字段必须保持同一
Raw 行关系的数组，以及来源尚未落地的标识继续阻断，直到有显式的元组依赖规则和合成回归。

### 2026-09-11 店铺范围包含来源命名空间

`store` 是规范实体类型，不足以证明某个外部数值可用于所有平台接口。Amazon `sid` 与多平台
`store_id` 分别使用 `store:{sid}` 和 `store:multiplatform:{store_id}` 来源键。资源契约增加
店铺命名空间，授权解析、计划扇出、依赖值范围和 Worker 请求都必须匹配该命名空间。
命名空间来源同时包含官方请求路径和官方文档模块；路径使用共用仓储前缀但文档归入
`MultiPlatform` 的接口不能回退为 Amazon。

一次 HTTP 200 的空结果不能证明跨命名空间参数正确。使用未批准命名空间形成的探测证据作废，
资源保持停用；Raw 作为审计材料保留但不投影。命名空间归属由人工审核来源目录记录，不按店铺
名称、平台名称或相同数值自动合并。

### 2026-09-11 字符串数组按单依赖值执行

只读接口要求 SKU/MSKU 字符串数组、且官方文档给出有限批量时，调度身份仍保存一个来源依赖
值；连接器只在请求边界包装为单元素数组。这样断点、重试和 Raw 血缘保持单值可追溯，后续可
在不改变范围模型的前提下增加确定性批处理。依赖值必须来自同一来源和当前获批店铺范围。
