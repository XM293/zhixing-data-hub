# ADR-023：领星来源镜像与独立规范映射

- 状态：accepted（用户于 2026-09-09 同意方案）
- 范围：DAT-011 后续来源层与受控服务器试运行

## 证据与调整

0066 基线已经有分页归档、checkpoint、离线 Raw 重放；正常采集仍在页事务内执行规范映射。映射失败会回滚采集台账，不能视为完整独立镜像层。调整 ADR-022 的单事务采集/映射要求：镜像模式中采集事务仅提交 manifest、采集水位和持久化映射任务，映射在另一个 Worker 任务内执行。

## 决策

- 保留 inline 请求兼容；新增显式 deferred 模式，采集成功仅表示来源数据已归档，不表示 Core 已就绪。
- 每个采集页唯一登记镜像页与映射运行关系。采集任务和映射任务使用独立状态、计数及 checkpoint；映射失败不得回退采集水位。
- 复用 Raw 重放执行器、后台任务租约、当前权限校验、哈希校验和映射版本检查，不建立第二套 HTTP 或认证实现。映射任务与镜像页必须在采集事务内一同提交，禁止双写窗口。
- schema_pending 页只采集，明确没有映射运行。后续确认 Schema 后才允许重新映射；不伪造稳定外部键、删除事件或业务口径。
- 重新映射更新镜像页的最近运行指针，历史运行及审计继续保留；已有映射运行排队或执行中时拒绝重复启动。来源接收计数和最近采集排除 raw_replay，避免离线读取被重复计算为外部采集。
- 原始页仍位于受控压缩归档。镜像页目录保存来源、资源、采集时间、页血缘和独立映射运行；可查询来源记录投影与批量重映射另行补齐，不能将页目录冒充完整 ODS。
- 初始迁移沿用当前数据库表命名空间，使用 source_mirror 前缀，保持 SQLite/PostgreSQL 验证兼容。专用 PostgreSQL schema/角色和跨库边界在服务器候选部署前单独验证，不声称表前缀提供权限或硬件隔离。
- 新的服务器受控试运行已获用户授权；不得先清理测试数据，不使用聊天中的旧凭据，迁移前备份并验证恢复。实际导入与本地合成验证分别记录。

## 验证门

公平续跑补充：真实库存批次持续产生 Raw 页，但队列原按 priority/created_at 领取，老任务续跑后仍先于等待中的映射和增量。改为 priority/available_at/created_at/id：保持显式优先级，同优先级按本轮可领取时间排队。续跑原本已更新 available_at，因此无需改写创建时间或迁移数据；租约、令牌及重试预算保持原约束。

售后范围补充：官方 Sale/afterSaleList 的 sid 为逗号分隔店铺 ID 字符串，不能沿用订单 sid_list 数组。项目范围售后请求复用可信店铺来源解析，并在 Raw 归档前校验响应 sid；当前沿用单分区最多 20 店铺的内部保护上限，不将其宣称为售后官方限制。日期仅按官方 Y-m-d 与 date_type=3 传递，时区未明确前不建立自动 UTC 增量水位。

2026-09-10 常驻运行补充：代码复核发现队列领取和调度发生数据库连接异常时会退出 Worker 主循环。常驻模式对 SQLAlchemy OperationalError / InterfaceError 做最高 30 秒的指数退避，成功轮询后重置；等待响应停止信号。只记录固定事件和异常类型，不记录数据库异常正文或连接参数。非连接类异常仍上抛，单次模式保持失败退出，避免隐藏部署错误。

2026-09-10 通用时间窗口补充：时间窗口由版本化资源目录声明字段名、来源格式和调度语义，计划只保存不会随时间移动的分区参数。API 把时区明确的 UTC 窗口按最多七天拆分，Worker 在外部请求前才生成来源要求的 `start_date/end_date` 或 `start_time/end_time`。已确认更新时间语义的资源使用 `updated_utc`；Schema 尚待确认但允许 Raw 探测的资源使用 `source_window`，该状态只表示可按来源时间范围归档，不表示具备可靠增量字段或可进入 Core。两类计划都只在子批次成功后推进水位，并按重叠窗口和每日回看重新采集迟到变化。

新增目录资源进入既有来源时必须先保持 `schema_pending`，即使代码目录已带规范映射，也不能因首次启用而绕过目录版本确认。移动时间字段不进入计划身份；店铺、区域和其他静态过滤条件继续进入身份、幂等键与 checkpoint 分区。

先证明采集页提交后 Core 仍为空、独立映射运行无网络执行、失败/撤权保留采集水位、重复采集不重复入队；随后补镜像查询、批量映射、Web 双状态和真实小窗口对账。DAT-011 在这些工作与原完成定义满足前保持 in_progress。
