# ADR-014：受治理数据范围映射与经营事实工具

- 状态：accepted
- 日期：2026-08-29
- 决策范围：客户数据接入、数据权限、AI 证据与 MCP

## 背景

平台访问范围使用稳定内部键，例如 `enterprise`、`store-flagship`；客户来源系统使用自己的业务键，例如店铺编码 `TM-001`。两者既不应假设相同，也不能在页面、Prompt、MCP 或权限判断中散落转换表。客户进场后店铺目录、组织范围和多来源编码都可能变化，硬编码会造成越权、漏数和重复定制。

规范经营事实已经保存外部店铺键与完整来源血缘，但在建立显式映射前，门店权限无法安全地下推到事实查询。MCP 也不能接受任意 SQL 或让模型自行猜测客户编码。

## 决策

新增 `DataScopeMapping`，按企业、来源、范围类型和外部业务键保存：

1. 平台 `scope_key`；
2. 来源 `external_scope_key`；
3. 标签、状态和扩展属性；
4. 来源 Schema、映射版本和实际同步批次；
5. 创建与更新时间。

连接器拥有外部字段解释权。同步店铺目录时，连接器在同一批次提交规范范围映射；数据中心幂等更新映射并保留当前血缘。上层只调用 `resolve_commerce_scope_keys`，不读取第三方字段。

`query_commerce_facts` 作为第四个 R0 工具发布到企业 API 与官方 MCP SDK 网关。工具只接受平台 `scope_key` 和结果上限，不接受 SQL、表名或外部店铺键；企业 API 使用可信 `ActorContext` 做权限和范围判断，再解析映射并返回订单、退款、库存、广告、异常与血缘视图。MCP 仍是工具访问层，不承担同步、仓储或权限真值。

经营分析复用同一事实查询。每次运行冻结指标序列、规范经营汇总和具体异常；所有证据使用唯一 `E` 编号并保存来源与同步批次。门店库存尚无可靠归属映射时返回未知，不把企业库存错误下放到门店。

## 客户适配

当前测试连接器用稳定规则生成 12 个店铺映射，仅用于验证契约。客户实施时可以由实际店铺目录、主数据维护或审核工作流产生映射。更换来源结构只修改连接器和映射版本，不修改权限角色、AI Prompt、MCP Schema 或前端页面。

同一平台范围可以映射到多个来源业务键；查询始终带 `enterprise_id` 并只读取状态为 `active` 的映射。缺失映射返回显式错误或数据缺口，不回退到企业全集。

## 后果

- 优点：客户编码变化被限制在接入边界，权限、AI 与 MCP 共享同一解析结果；
- 优点：员工门店查询与 CEO 企业查询可以自动化验证，事实来源可重放；
- 优点：Codex 获得稳定只读工具，不需要理解客户数据库结构；
- 代价：范围映射需要版本、冲突检测、审核和实施维护；
- 限制：当前只覆盖企业与店铺范围，仓库、组织、商品和渠道复合范围将在真实客户结构明确后扩展。

本 ADR 不改变正式 `DAT-*`、`IAM-*` 或 `OPS-*` 任务依赖，也不代表生产权限配置和客户对账已经完成。
