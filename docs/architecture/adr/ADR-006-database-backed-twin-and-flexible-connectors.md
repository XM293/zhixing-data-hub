# ADR-006：以数据库驱动的企业数字孪生替代纯静态验收

- 状态：Accepted
- 日期：2026-08-25
- 决策范围：M0 产品验收、数据底座和外部系统适配

## 背景

产品负责人否决了纯 Fixture 驱动的全景原型。主要问题不是页面数量，而是静态样机无法证明数据中心、外部接入、持久化状态和跨模块运行关系，视觉上也不足以代表最终企业 AI 数据中心。

同时，客户现场的吉客云、CRM、店铺后台和自建系统字段尚不明确。如果现在把某一客户字段直接固化到核心表，进厂后会造成结构性返工。

## 决策

### 1. 增加数据驱动产品验收切片

`/console` 企业数字孪生首页只从产品 API 读取，不从前端 Fixture 读取。首页显示的企业、来源状态、指标、同步批次、节点、连线和事件必须来自持久化数据库。

其他尚未重做的页面继续保留 `prototype` 标识，不能因首页接入真实数据库而声明整个产品已经实现。

### 2. 数据接入采用三层结构

```text
第三方 API
  -> SourceRecord 原始记录（保留原字段、来源版本和内容哈希）
  -> Connector Mapping（独立适配器、mapping_version）
  -> Canonical Projection（企业实体、指标快照和孪生运行状态）
```

第三方字段只能出现在连接器和原始记录中。标准实体、指标和上层模块不得依赖 `shop_code`、`paid_gmv_fen` 等供应商字段。每次同步保留 `source_schema_version`、`mapping_version`、`sync_run_id` 和 `enterprise_id`。

客户字段变化时优先新增映射版本；确需扩充标准模型时通过迁移完成，不覆盖历史原始记录。

### 3. 提供独立第三方测试沙箱

`services/mock-commerce` 模拟客户侧电商聚合服务，使用第三方风格字段并支持：

- `normal`：完整成功；
- `delayed`：延迟响应；
- `partial`：广告资源失败、其他资源可用；
- `failure`：连接失败。

沙箱同时提供 `small`、`standard`、`large` 三个确定性数据规模档位，覆盖店铺、商品、SKU、仓库、客户和订单。同步批次持久化 `scenario` 与 `volume_profile`，分别验证故障行为与数据体量，不能把两者混为一个演示开关。

沙箱不是产品业务数据库，也不与产品 API 共享表或 Python 内部模型。该边界用于验证连接器确实通过 HTTP 契约工作。

### 4. 本地与客户环境使用同一迁移模型

- 无 Docker 的开发环境默认使用 `services/api/var/zhixing.db` 持久化 SQLite；
- 客户环境和完整本地基础设施使用 PostgreSQL 16；
- 两者均由 Alembic 管理迁移；
- PostgreSQL/MinIO Compose 放在 `deploy/local/compose.yaml`；
- SQLite 只作为单机开发后端，不改变生产数据库选择。

### 5. Three.js 用于运行关系，不替代业务界面

Three.js 场景表达企业系统、数据中心、知识、记忆、分身、会议、分析和行动之间的实时拓扑。节点健康、状态和流量来自 API；点击节点联动详情。3D 首页不承载复杂 CRUD，列表、配置、审计和审批仍使用高密度二维企业界面。

## 与既有验收门的关系

本 ADR 修订 ADR-005 的“全程纯模拟”限制，但不取消产品负责人验收门：

- `UIA-006` 继续阻塞 `DOM-001`；
- 当前数据库表是可运行的接入底座与查询投影，不自动成为所有领域的最终真值模型；
- 身份、知识、记忆、会议、行动等完整领域模型仍按既有任务依赖实现；
- 产品负责人需要重新验收视觉系统、数据中心表达和模块动线。

## 验收标准

- 空库可重复升级并写入初始企业与拓扑配置；
- Web、产品 API、第三方沙箱可由一个命令启动；
- 正常和部分失败同步均有自动化或端到端验证；
- 浏览器显示的数据可在数据库中追溯到同步批次和原始记录；
- 桌面与移动端 Three.js 画布非空、可交互、无明显遮挡；
- 浏览器控制台无错误。
