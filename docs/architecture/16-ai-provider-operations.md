# AI Provider 运行控制与审计

- 日期：2026-08-29
- 数据库修订：`0026_ai_provider_operations`
- 适用范围：平台管理员的模型接入诊断与运行质量观察

## 1. 目标与边界

AI 运行控制台统一观察分身问答、数字会议、经营分析、客服草稿、单客运营方案和评测运行，回答“当前模型是否可用、哪些业务在调用、成功与降级比例如何、耗时和 Token 是否可追溯”。它是现有运行记录的数据库投影，不是新的 Agent Runtime，也不提前完成仍受依赖阻塞的 `OPS-004`。

平台管理员通过 `ai.provider.manage` 访问该页面和探针接口。CEO、部门经理、员工及客服角色不能读取 Provider 配置状态或执行探针。前端菜单只是权限投影，API 仍按企业、权限、资源和范围执行授权。

## 2. 接口与持久化

```text
GET  /api/v1/ai-operations/overview
POST /api/v1/ai-operations/probes
```

`AIProviderProbeRun` 只保存企业、执行主体、Provider 标识、模型、协议、结构化输出能力、结果、耗时、Token、脱敏错误、`request_id`、`run_id` 和时间。数据库与响应均不保存或返回 API 密钥、Prompt、完整端点 URL、企业资料或模型输出正文。

探针调用最小固定输入并要求严格 JSON Schema；失败记录会清理 URL、Bearer 值和常见 key/token 形式。探针只验证当前连接与结构化输出能力，不代表业务回答质量已经通过。

## 3. 统计口径

- `AgentRun` 统计分身问答、评测案例、数字会议各阶段和客服草稿；
- `BusinessAnalysisRun` 单独统计经营分析，按真实模型和证据降级区分运行模式；
- `CustomerOperationRun` 单独统计单客运营方案，按真实模型和规则回退区分运行模式，并保留冻结证据快照；
- `EvaluationRun` 只计评测批次，不重复计入总 AI 运行；评测实际回答已经作为 `AgentRun` 计数；
- 14 日趋势按运行创建时间和企业边界聚合；最近运行台账最多返回 30 条；
- Token 覆盖率只表示有 usage 数据的运行比例，不能把缺失 Token 当作零成本。

## 4. 真实验收记录

2026-08-29 使用当前私有兼容 Responses Provider 完成两次结构化输出探针，均由 `gpt-5.4-mini` 返回严格 JSON Schema 结果。随后运行 `m1-role-twin-smoke` v1 的 7 个案例：5 个自动通过、2 个按案例规则进入人工复核、0 个失败、0 个运行错误，耗时约 67 秒。

评测后控制台汇总 105 次 AI/经营分析运行，其中 79 次真实模型成功、26 次证据降级，成功率约 75.2%；包含 53 次会议阶段运行、47 次分身问答与评测、3 次客服草稿、2 次经营分析和 2 个评测批次。新增的 6 次模型回答均以 `model` 模式、`openai-compatible-responses` Provider 和 `gpt-5.4-mini` 写入不可变运行台账。

已确认决策的数字会议再次运行时返回 `meeting.confirmed_decision_locked`，没有覆盖既有 53 条会议阶段记录。该限制用于保护已确认决策和后续行动链路；需要再次研判时应创建新议题，而不是修改或删除确认记录。

## 5. 后续演进

正式运维看板仍需在依赖满足后补充模型单价和版本化计费、渠道/角色/工具维度、延迟分位数、告警阈值、后台评测队列、保留策略和生产环境指标采集。Provider 适配器继续由服务端配置装载；凭据不得进入仓库、数据库业务表、浏览器响应或运行文档。
