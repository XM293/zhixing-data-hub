# 数字会议协议 v0.1

## 目标

让多个管理者分身和专业智能体围绕同一组企业证据进行独立分析、质询和决策整理，而不是简单地让多个模型轮流发言。

## 参与者类型

- 管理者分身：CEO、运营、财务、供应链、人力等。
- 专业智能体：数据分析、财务审查、合规、客户之声。
- 反方智能体：寻找错误激励、遗漏风险和反事实。
- 主持与秘书：控制流程、汇总证据和形成决策包。

## 状态机

```text
DRAFT
  → EVIDENCE_FROZEN
  → INDEPENDENT_ANALYSIS
  → CROSS_EXAMINATION
  → RISK_REVIEW
  → DECISION_DRAFTED
  → HUMAN_CONFIRMED
  → ACTIONS_CREATED
  → REVIEWED
```

## 会议步骤

1. 登记议题、决策负责人、期限和成功指标。
2. 冻结数据、制度、指标和记忆版本，创建 EvidenceSnapshot。
3. 各分身独立分析，输出主张、证据、假设、置信度和未知项。
4. 进行最多两轮交叉质询，禁止没有新证据的重复表态。
5. 反方智能体检查错误激励、反事实和失败退出条件。
6. 主持智能体整理方案比较、共识、分歧和待确认项。
7. 人类负责人确认或退回。
8. 生成任务、负责人、期限、KPI和复盘时间。
9. 复盘实际结果，将经验写入知识或记忆候选队列。

## 决策包结构

- 议题与决策范围。
- 证据快照和数据时间。
- 各方独立观点。
- 关键主张、证据和反驳。
- 方案比较与敏感因素。
- 共识、分歧和未知项。
- 人类最终结论和保留意见。
- 行动项、负责人、期限、指标和退出条件。
- 复盘日期与实际结果。

## 首期限制

M1 支持从已发布分身中选择 3–6 位角色、三个受治理会议模板、企业或授权门店范围、两轮质询和人工确认，不实现开放式无限对话或自由修改协议。会议输出不直接触发外部业务操作。

## 2026-08-29 纵向切片实现状态

当前已经打通从证据冻结、两轮审议到人工确认和内部行动创建的数据库纵向切片，尚未宣称整个 M2 数字会议域完成：

| 协议阶段 | 当前实现 | 持久化结果 |
| --- | --- | --- |
| 受治理创建 | 校验发起权限、数据范围、模板、3–6 位已发布分身和请求幂等性 | `twin_meetings`、`twin_meeting_participants`、`twin_meeting_seats` |
| 证据冻结 | 从有效知识版本、经营指标和已批准角色记忆生成不可变快照 | `evidence_snapshots`、`evidence_snapshot_items` |
| 独立分析 | CEO、运营、财务并行执行，首次分析互不可见 | 3 条 `meeting_claims`、3 条 `agent_runs` |
| 第一轮质询 | CEO → 运营、运营 → 财务、财务 → CEO 循环挑战 | 3 条 `meeting_deliberation_turns` |
| 第二轮回应 | 被挑战角色逐一回应，明确立场是否变化 | 3 条 `meeting_deliberation_turns` |
| 反方审查 | 检查失败机制、错误激励、反事实、退出条件和证据缺口 | 1 条 `meeting_deliberation_turns` |
| 主持汇总 | 汇总独立意见、两轮质询和风险审查 | 1 条 `decision_packages` |
| 人工确认 | 有权限的人类负责人锁定决策包；重复提交保持幂等 | 1 条 `meeting_decision_confirmations` |
| 行动创建 | 按决策包行动顺序生成稳定、可追溯的内部提案 | N 条 `action_proposals` |
| 内部审批 | 审批人与提案人分离，结论不可被后续请求改写 | `action_approval_events`、`action_executions` |

单次运行包含 11 个可审计 AgentRun：3 次独立分析、6 次质询/回应、1 次风险审查和 1 次主持汇总。业务结果按会议、角色和阶段幂等更新，因此重复运行会保留 3 条独立观点、7 条审议记录和 1 份决策包，不会把同一轮次重复追加到会议台账。

### 证据与质量约束

- 指标证据严格限制为会议的企业或门店 `scope_key`；记忆证据只允许来自本次所选角色分身。
- 所有 `E` 编号必须属于本次冻结快照，非法引用直接拒绝。
- `new_evidence_refs` 必须属于该条发言的全部引用，并且整轮至少包含一项该角色此前未使用的冻结证据。
- 服务端会把模型分散填写在 `new_evidence_refs` 的引用规范化到 `evidence_refs`，但不会替模型创造新的证据。
- 输出中的数字和日期必须能在输入证据中找到；擅自增加精度、编造阈值或日期会触发降级。
- 质询阶段的结构化输出、证据引用、新颖性或数字校验失败时，先把具体错误和允许的新证据引用反馈给模型纠正一次；仍失败才只降级当前阶段为确定性证据模板，其余阶段继续运行。
- 其他阶段校验失败时只降级当前阶段；所有降级原因写入 `agent_runs.fallback_reason`，不会伪装成模型成功。
- 每个阶段均保存模型、耗时、令牌量、证据关系和平台事件，用于后续审计与评测。

### 创建、身份与范围

- `/console/meetings` 的议题编排台从 API 读取模板、授权范围和已发布分身，不硬编码客户门店键。
- 创建请求保存幂等键与请求哈希；同一请求重试返回同一会议，复用幂等键提交不同内容会被拒绝。
- 列表、创建、详情、运行和确认都从可信 `ActorContext` 检查权限与对象范围；每个会议 `AgentRun` 记录实际发起主体。
- 企业范围统一为 `enterprise`；门店范围由指标目录、既有会议与主体范围授权合并生成，并逐项经过范围校验。
- 会议创建时冻结所选分身版本与席位，后续分身配置更新不会悄悄改变本次会议阵容。

### 当前行动边界

- 人工确认后，协议状态进入 `ACTIONS_CREATED`，决策包被锁定，不允许重新生成覆盖已确认结论。
- 当前审批只登记企业内部行动台账，`action_executions.external_write` 固定为 `false`；不会写入飞书任务、ERP、店铺后台或其他外部系统。
- 本地开发身份头只选择数据库中的测试账号；权限、范围和主体均由服务端数据库解析，用于验证 401、403、权限分离和幂等语义，不等同于正式登录与 SSO 已完成。

### 尚未完成

正式账号认证、组织子树与知识空间范围配置、委托授权、外部审批与任务执行、失败补偿和复盘回写仍需按 IAM、行动中心与评测任务继续实现。当前企业/门店范围纵向切片只证明统一授权契约可运行，不代表所有客户组织模型已经覆盖。三维会议室是同一会议业务键的空间投影，不替代上述协议状态机。
