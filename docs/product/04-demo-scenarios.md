## 2. 场景 A：制度更新到员工问答

### 初始状态

- `policy-kpi-v3` 为待发布，生效日期 2026-09-01。
- 一条聊天记忆声称旧的退款率规则仍有效，状态为 `conflict`。
- 员工陈曦只能访问运营中心制度和本人任务。

### 操作路径

1. 管理员视角进入知识中心的制度版本页。
2. 查看 v2 与 v3 的生效关系，执行“发布演示版本”。
3. CEO 视角进入记忆审核，批准“以 v3 制度为准”的候选，拒绝冲突旧规则。
4. 切换员工视角，在全局助手提问“9 月退款率如何考核？”
5. 回答显示制度 v3、生效时间和原文定位；不得引用被拒绝记忆。

### 验收

- 发布和审核状态跨页面一致。
- 回答区分事实与管理建议。
- 员工看不到 CEO 私有记忆正文。

## 3. 场景 B：经营异常到数字会议

### 初始状态

- 旗舰店昨日 GMV 为 128.6 万元，较 7 日均值增长 12.4%。
- 广告花费增长 31.8%，广告 ROI 从 3.42 降到 2.68。
- 可售库存覆盖 18 天，退款率 4.7%。

### 操作路径

1. CEO 工作台进入广告 ROI 异常。
2. 店铺诊断展示指标口径、来源和数据截至时间。
3. 点击“发起数字会议”，进入 `mtg-budget-20260825`。
4. 查看 CEO、运营、财务三角色独立分析和两条分歧。
5. 生成决策包：不立即全面加预算，先进行 7 天、20 万元上限的素材测试。

### 验收

- 所有角色使用同一证据快照。
- 财务风险意见不能被主持汇总删除。
- 决策包链接到原指标与制度版本。

## 4. 场景 C：决策到行动审批

### 初始状态

- `act-budget-test-01` 为待审批，风险级别 R2，只生成内部测试计划草稿。
- 发起人为 CEO，审批人为运营经理，未绑定真实广告平台写操作。

### 操作路径

1. 从决策包进入行动提议。
2. 查看目标店铺、预算上限、7 天周期、证据和幂等键。
3. 切换运营经理视角，批准模拟行动。
4. 执行台账显示 `simulated_succeeded` 和复盘日期。

### 验收

- 审批前后状态一致且可追溯。
- 页面持续显示“仅演示，不会修改外部系统”。
- 发起人、审批人和执行主体分别展示。

## 5. 场景 D：客服辅助回复

### 初始状态

- `cnv-10086` 客户订单物流延迟 3 天。
- 物流接口最近同步时间为 09:18。
- 客户请求 100 元补偿，超出客服可承诺范围。

### 操作路径

1. 客服视角打开待回复会话。
2. 查看订单、物流、商品和客服规则上下文。
3. 生成解释物流状态的回复草稿。
4. 系统识别补偿承诺风险，禁止自动确认金额并提示转人工。

### 验收

- 草稿引用物流时间和客服规则版本。
- 不模拟真实发送。
- 风险场景提供清晰转人工入口。

## 6. 状态样例

原型固定保留以下非理想状态：

- 吉客云最近同步成功；广告平台同步延迟；CRM 同步失败。
- 制度库存在待发布版本和一处记忆冲突。
- 一个后台任务可重试，一个任务等待人工处理。
- 员工访问平台权限页显示无权限状态。
- 空状态通过角色或筛选条件触发，不单独伪造无关页面。
