- 任务：UIA-001
- 日期：2026-08-25

## 1. 导航层级

管理台使用“空间工作台 + 经营驾驶舱 + 七个核心中心 + 客服业务工作台”的结构。空间工作台承接数字孪生交互，驾驶舱汇总经营和平台态势，核心中心管理企业资产，客服工作台作为首个受控业务应用纵向切片，不把客服领域混入数据或行动真值。

| 一级入口 | 默认路由 | 主要对象 | 首批深度 |
|---|---|---|---|
| 工作台 | `/console` | 指标摘要、异常、待办、会议、行动 | 完整角色首页 |
| 企业经营驾驶舱 | `/console/cockpit` | 经营指标、数据资产、平台节点、运行事件、建设差距 | 数据库实时大屏 |
| 企业数据中心 | `/console/data/sources` | 数据源、任务、经营事实、客户 360、实体、指标、质量 | 数据库运行页 + 经营工作台 |
| 企业知识中心 | `/console/knowledge/documents` | 文档、制度、导入、证据 | 数据库目录 + 版本/切片/检索 |
| 角色分身中心 | `/console/twins/instances` | 模板、分身、记忆、Prompt、测试 | 列表 + 审核流程 |
| 数字会议中心 | `/console/meetings` | 议题编排、范围、角色阵容、分析、质询、决策包 | 受治理创建 + 会议过程 |
| 智能分析中心 | `/console/analysis/store-review` | 问数、诊断、巡店计划、简报 | 诊断 + 证据 + 受治理调度 |
| 行动与执行中心 | `/console/actions/work` | 工作承接、提议、审批、执行 | 运营工作台 + 审批流程 |
| 客服工作台 | `/console/customer-service/conversations` | 数据库会话、订单上下文、证据草稿与人工接管 | 已实现纵向切片 |
| 平台管理 | `/console/admin/users` | 账号、组织岗位、访问角色、范围、渠道、AI Provider、工具、任务、授权审计 | 数据库运行纵向切片 + 待实现配置页 |

## 2. 角色首页

### CEO

- 企业关键指标与昨日、近 7 日对比。
- 需要判断的经营异常和证据时间。
- 待确认决策包、待审批行动和近期会议。
- 从异常进入诊断、从诊断发起会议的连续动线。

### 部门经理

- 本部门和授权店铺指标。
- 待处理任务、制度更新和团队异常。
- 店铺诊断、岗位指导和行动审批入口。
- 不显示企业级敏感指标和平台配置。

### 员工

- 制度与岗位问答作为主操作。
- 我的任务、最近制度更新和已关注店铺。
- 反馈、纠错和转人工状态。
- 不显示他人记忆审核、企业全局经营和系统配置。

### 平台管理员

- 数据源与后台任务健康状态。
- 待绑定渠道身份、失败任务和权限变更。
- 用户组织、工具注册、提供者和审计入口。
- 不模拟管理员天然拥有业务决策权。

### 客服

- 待回复会话、响应时长和风险会话。
- 订单物流上下文、规范交易事实、关联状态和字段级对账结果。
- 金额、状态、件数或退款冲突显示两套值、差异等级和 AI 门禁，不用一个“已关联”标签代替对账。
- 补偿承诺、退款等操作只显示转人工。

### 企业经营驾驶舱

`/console/cockpit` 是工作台下方的独立一级入口，面向 CEO、部门经理和平台管理员。页面直接读取数据中心概览接口，展示经营指标变化率、数据库资产体量、平台节点分布、数据来源状态、运行事件与数字会议进度。

驾驶舱不得用前端随机数补齐趋势。当前接口只有指标快照时，只绘制真实变化率并明确提示缺少历史序列；规模化差距区持续展示真实连接器、原始记录、统一实体和经营维度距首期接入验收基线的差距。该基线用于判断第一批真实数据能否支持回放、查询和分析，不代表生产容量上限。

驾驶舱支持从管理后台直接进入浏览器全屏，大屏模式只保留经营内容，不显示侧栏和顶栏；退出后回到原管理台上下文。1500–1799px 的高 DPI 有效视口、1800px 工作站和 2200px 以上超宽屏分别使用独立信息密度档位，避免将 1440px 字号简单拉伸到超宽屏；高度为 760–899px 时，全屏大屏压缩图表纵向间距并把长台账收敛到面板内部滚动。

驾驶舱首屏只保留六项核心经营指标和七类数据库资产族，其中原始业务记录与规范经营事实独立统计。知识文档、版本、切片以及分身、运行、工具调用等表级明细仍由各中心完整展示，驾驶舱不通过缩小字号把 21 项指标或所有底层表数量强行塞进首屏。数字孪生工作台在基础桌面档同样保证场景标题、对象详情和底部指标可读；1500–1799px 档专门处理系统缩放后的可读性与浮层避让，1800px/2200px 档再逐级提升空间密度。

### 数据源与接入运行

`/console/data/sources` 直接读取数据中心概览接口，展示来源注册、数据契约、映射版本、同步批次、数据库资产规模和连接器适配方式。页面用当前数据库数量与下一阶段接入基线对照，明确区分“链路已验证”和“生产规模已具备”。

数据基线必须同时显示当前值、目标值和覆盖率。当前数据库的覆盖率为：测试来源 100%、原始记录 45.9%、统一实体约 27.1%、经营指标 70%；规范经营事实另按订单、订单行、退款、库存与广告日绩效的客户验收口径逐类对账，不用原始记录目标掩盖领域缺口。这些数据证明四来源隔离、映射、持久化、分页和 90 天趋势链路可运行，不代表生产分析能力已经具备。

接入层按开放 API、数据库/CDC、文件批量和消息事件四类适配，业务页面只依赖统一来源与同步模型。每个已注册测试源可以独立选择数据规模并运行同步，原始记录、Schema、映射版本和批次按来源隔离；客户真实系统的数据结构在实施阶段通过替换对应连接器和提升映射版本调整，不要求重写驾驶舱或上层分析页面。

平台授权范围与客户外部店铺编码使用数据库 `DataScopeMapping` 连接。经营事实页面、AI 诊断和 `query_commerce_facts` MCP 只接收平台范围键，并共用服务端解析器；门店没有库存归属映射时明确显示缺口，不回退到企业库存。当前大型档同步形成 12 个有效店铺映射，客户实施可以替换映射来源和版本而不改变页面权限模型。

数据中心二级入口按服务端权限投影：来源和同步任务只对数据管理员显示；实体、指标与质量要求口径治理权限；经营事实与客户 360 对具备相应读取权限的经理和员工显示。经营事实页面从当前会话的允许范围生成选择项，企业主体默认企业全域，门店主体默认首个授权门店；直接调用 API 仍会再次执行功能权限和范围检查并记录授权决策。

## 4. 共用页面模式

- 列表页：标题、状态摘要、搜索/筛选、表格、选择态、详情区域。
- 详情页：对象标识、状态、负责人、业务时间、版本、来源、主内容、时间线。
- 工作台：指标条、异常列表、待办列表和近期活动，不堆叠装饰卡片。
- AI 结果：指标趋势与规范经营事实分层，事实、推断、建议、未知分区，并展示证据、来源批次和 `as_of`。单客运营方案必须显示真实模型或规则回退、冻结证据、发起人、风险与人工审批边界。
- 审批：影响对象、前后变化、风险、发起人、审批人和模拟执行说明。
- 错误：明确失败对象、最近成功时间、重试入口和 run_id。

### 数字会议编排模式

- 议题编排台作为列表页内的全宽工作区展开，不用窄弹窗承载复杂角色和范围选择。
- 模板只提供受治理的协议参数和默认文案；客户后续模板配置不会改变会议状态机与审计字段。
- 数据范围由 API 按当前主体动态返回企业与门店选项，前端不保存客户门店编码白名单。
- 参会分身只显示已发布版本，至少 3 位、最多 6 位；创建后保存角色、版本和席位快照。
- 失败重试沿用同一幂等键，避免网络或模型延迟造成重复会议。
- 详情页同时展示八阶段协议状态、冻结证据、独立观点、两轮质询、反方审查、决策包和人工确认闸门。

## 5. 响应式范围

- 1440×900：完整侧栏、密集表格和双栏详情。
- 2515×1199：空间页浮层与经营驾驶舱使用工作站尺寸，常规数据页取消固定内容宽度上限；1500 CSS 像素以上的高 DPI 视口同样使用全高数据工作区。
- 1024×768：收窄侧栏，主区域保持列表可扫描。
- 390×844：抽屉导航，指标和表格转为纵向摘要，保留问答和审批主操作。
- 移动端不承担复杂实体映射和权限批量配置，只保证安全查看和轻量处理。
