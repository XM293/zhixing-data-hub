## 2. 三维成熟度模型

以后所有模块必须同时记录三个维度，不能用一个 `done` 或“页面已出现”概括全部状态。

| 维度 | 取值 | 含义 |
|---|---|---|
| implementation | absent / prototype / implemented-slice / implemented | 代码、数据库、API、页面和测试是否贯通 |
| product_acceptance | blocked / review / accepted | 是否通过产品负责人或领域负责人验收 |
| production_readiness | unavailable / dev / pilot-ready / production-ready | 是否具备真实身份、真实数据、容量、备份、监控、回滚和外部责任条件 |

当前任务索引中的 `blocked`、`review` 和 `done` 主要表示计划依赖与验收状态，不等于 implementation 状态。特别是 `UIA-006` 是人工产品验收门，未获得产品负责人确认前，不能把 `DOM-*` 和后续正式领域任务批量改为 `done`。

## 4. 架构基线与冲突处理

### 4.1 集团多法人

现有 `enterprise_id` 保持法人企业语义，不能改成集团 ID。集团、多子公司和不同电商业务采用：

```text
Group
└── LegalEnterprise (enterprise_id)
    └── BusinessUnit
        ├── Brand / Market / Store
        ├── Warehouse
        └── Org / Position
```

国内电商、海外电商、选品事业部不能全部建成独立代码分支，而应由 `EnterpriseOperatingModel` 和能力包配置：

```text
OperatingModel
├── MetricPack
├── KnowledgePack
├── SkillPack
├── ConnectorPack
├── CenterAssignment
├── Currency / Timezone / Tax
└── SceneProfile
```

集团总览、子公司空间、业务单元空间使用同一场景契约和 `scope_key`，但数据、知识、指标、Skill、菜单和 3D 节点按当前 `ScopeContext` 投影。集团合并必须携带范围、币种、汇率版本、抵消规则、数据截至时间和参与企业集合。

2026-09-09 本地已移除生产运行路径中的演示企业默认值并补充静态回归；演示 seed 和合成测试保留。ScopeContext v2、集团/法人/项目治理、来源归属、Worker 入队分页和规范事实范围查询已实现；MCP 跨法人再授权及范围收窄、Runtime 快照与续问范围检查继续补齐。旧指标/工作台查询和集团合并口径仍未全部接入，不能宣称集团运行时已完成。具体决策见 `ADR-022`，当前证据见 `docs/reports/dat-011-lingxing-local-verification.md`。

### 4.2 数字孪生定位

Three.js 继续作为浏览器端空间投影技术，不切换 Babylon.js、Unity 或 Cesium。数字孪生不是第二套业务真值，也不替代后台：

```text
三维空间：认知、关联、下钻、运行现场
二维中心：明细、治理、批量操作、审批
AI Runtime：解释、分析、会议、建议
Action：审批、承接、执行、复盘
```

开发顺序采用“先骨架、后闭环、再精致化”：先保证集团/子公司/业务单元空间和稳定对象键，再将真实 Read Model 和事件接入，最后接入 GLB/GLTF、LOD、InstancedMesh、骨骼人物和高精度材质。

### 4.3 Skill、MCP 与 Runtime

Skill 是编排层，不是权限、知识库或数据仓库。Skill 只能引用 Tool Registry 中已登记的工具，实际运行权限仍由 ActorContext、ScopeContext 和 MCP Gateway 决定。后续需要把已注册 Skill 注入 Runtime 运行规格，但不把供应商 Skill ID 写入平台领域真值。

### 4.4 文档与任务状态冲突

代码已经领先于任务索引。不能简单把所有 blocked 改成 done，也不能让新开发者认为 blocked 就等于没有代码。后续用本总账区分：已实现切片、待产品验收、待生产化。
