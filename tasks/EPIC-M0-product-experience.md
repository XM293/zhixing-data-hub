# M0：产品全景原型与验收任务包

## 目标

交付可以实际操作的数据驱动产品全景，让产品负责人提前确认导航、角色工作台、关键页面、数据结构和跨模块业务流程。纯 Fixture v0.1 已被产品负责人否决，当前按 ADR-006 先重做数据库底座、连接器沙箱和企业数字孪生首页。

本任务包只增加验收步骤，不改变既有领域边界和“管理者分身优先”的真实开发顺序。

## 执行顺序

```text
FND-004
   ↓
UIA-001 → UIA-002/UIA-003 → UIA-004 → UIA-005 → UIA-006
                                                    ↓
                                                 DOM-001
```

岗位工作空间改造作为现有全景验收的补充门：

```text
UIA-001 → UIA-002 → UIA-009
                       ↓
                角色化首页与导航投影
```

`UIA-009` 的详细边界、工作空间目录、Read Model、AI 上下文和 3D 降级规则见 `docs/development/07-role-oriented-workspace-modification-guide.md`。它不新增第二套权限系统，也不改变数据、知识、记忆、分身、会议或行动领域的真值所有权。

`FND-005`、`FND-008` 和 `FND-009` 可以与 UIA 任务并行；业务领域实现必须等待 `UIA-006`。

## 任务组

- `UIA-001`：确认角色视角、信息架构、页面地图和演示故事。
- `UIA-002`：建立管理台应用壳、视觉规范和全局状态。
- `UIA-003`：建立 UI Read Model、稳定 Fixture 和模拟数据源。
- `UIA-004`：完成全部核心中心代表性页面。
- `UIA-005`：完成客服预览和四条跨模块演示故事。
- `UIA-006`：产品负责人全景验收和范围冻结。
- `UIA-009`：建立岗位工作空间、角色化首页和导航投影；依赖 UIA-002 与统一授权服务，完成后再收口各岗位首屏。

## 原型真实性规则

- 已接入页面明确显示数据库、测试沙箱或生产数据状态；未接入页面持续显示演示状态。
- 同一对象跨页面使用同一稳定 ID、名称、数值、状态和版本。
- 模拟命令可以改变演示状态，但不调用真实外部系统。
- 页面覆盖正常、加载、空数据、失败、部分延迟和无权限。
- 模块交付状态区分 `prototype` 与 `implemented`。
- UI Read Model 不生成数据库表，不改变领域真值所有权。

## 验收演示

产品负责人依次切换管理员、员工、CEO、部门经理和客服视角，完成组织授权、制度发布、分身问答、经营异常分析、数字会议、行动审批和客服草稿流程。桌面端和移动端均可使用，演示数据和未实现能力明确可辨。

## 退出条件

- 导航、页面地图、角色首页和四个代表性故事获得产品负责人确认。
- 所有核心中心至少有一个可操作代表性流程。
- 关键 Read Model、Fixture 和模块清单有自动化契约检查。
- Playwright 关键流程、响应式和控制台检查通过。
- `docs/reports/m0-product-experience-review.md` 记录保留、修改、删除和后续优先级。
- 产品负责人明确同意解锁 `DOM-001`。
