# M0：平台骨架任务包

## 目标

完成未来系统共用的代码骨架、产品全景验收、领域契约和 Codex 研发规范，不做空洞的大平台功能。M0 先让产品负责人看到并确认整体体验，再在不改变领域边界的前提下建设真实底座。M0 结束后，管理者分身可以在稳定边界上开发，数据中心、会议和执行模块已有明确扩展点。

## 执行顺序

```text
FND-001 + FND-002
        ↓
FND-003 → FND-004/FND-005 → FND-006/FND-008/FND-009
                                   ↓
                                FND-010

FND-004 → UIA-001 → UIA-002/UIA-003 → UIA-004 → UIA-005 → UIA-006
                                                              ↓
DOM-001 → DOM-002..007 → DOM-008 → AGT-001/EVA-001
    ↓                       ↑
 IAM-001 → FND-007 → IAM-002/IAM-003
                         ↓        ↓
                      IAM-005   IAM-007

FND-010 + IAM-002 + IAM-003 + IAM-007 → IAM-004
```

## 必须交付

- 可启动的Web、API、Worker和本地依赖。
- 可切换角色、覆盖全部产品中心并串联关键故事的产品全景原型。
- 产品负责人完成 `UIA-006` 验收并形成版本化范围结论。
- 数据、知识、记忆、角色、证据、运行和行动Schema。
- 数据库迁移、日志、错误结构和基础CI。
- 企业、用户、组织、岗位、任职、访问角色、数据范围和 ActorContext 契约。
- 通用 Worker、PostgreSQL 任务表、重试和幂等基础能力。
- 管理台应用壳根据有效权限生成菜单；未实现模块明确标记为规划中，不制作虚假功能页面。
- Codex可以通过任务ID完成一次端到端开发、测试和文档更新。

## 验收演示

第一段验收使用统一演示数据切换管理员、员工、CEO、经理和客服视角，完成制度发布、分身问答、经营分析、数字会议、行动审批和客服草稿。产品负责人确认导航、页面与流程后，第二段从空目录环境启动真实底座，创建企业、用户、部门、岗位、任职和访问角色；通过 FakeRuntime 以员工身份调用 Mock 分身，保存 ActorContext、AgentRunEvent 和 EvidenceSnapshot Mock，并在管理台看到授权结果与运行记录。

## 非目标

- 不接真实模型和业务系统。
- 不部署OpenMetadata、Temporal或完整湖仓。
- 不为每个领域创建独立微服务。
- 不建设复杂 SaaS 租户运营后台或通用策略语言。
- 不因全景原型而提前创建所有业务数据库表或接入真实业务系统。
