# M3：运营执行任务包

## 目标

从“回答和建议”推进到“可控行动”，先做只读巡店和草拟，再选择一个低风险写操作验证审批、幂等、失败处理和审计。

## 行动阶梯

1. 读取：查询经营事实和业务状态。
2. 分析：识别异常、解释原因、提出建议。
3. 草拟：生成飞书任务、内部回复或操作计划草稿。
4. 审批后执行：调用一个低风险业务接口。
5. 受控Computer Use：仅在无API软件中POC。

## 第一个场景：每日巡店

系统每日读取销售、退款、广告和库存，比较昨日、近7日和目标值，识别异常，生成带证据的飞书早报。第一版不自动调价、退款或修改广告预算。

## 第一个写操作选择标准

- 可在测试环境验证。
- 有明确幂等键和结果查询。
- 失败后可人工恢复。
- 不涉及资金划转、退款、调价、发货或对客承诺。
- 能证明行动中心的通用流程，而不是写一次性脚本。
- 发起人、审批人和执行主体可分别识别；权限范围可在执行时重新判断。

## 退出条件

- 所有写操作先产生ActionProposal。
- 审批前源系统无状态变化。
- 重复请求不会重复执行。
- 失败保留证据并能由人处理。
- 执行前重新授权；权限已撤销、范围变化或审批失效时不得写入外部系统。
- 审批人与执行主体、ActorContext 和授权决策可完整审计。
- 根据真实任务需求决定是否引入Temporal。
