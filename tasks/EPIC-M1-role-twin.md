# M1：管理者分身试点任务包

## 目标

以通用角色分身平台为产品能力，配置CEO作为第一个真实实例，打通知识、记忆、Codex Runtime、Web、飞书、反馈和评测。

## 工作流

```text
制度原件 → PolicyVersion → KnowledgeProvider → 标准引用
聊天记录 → MemoryCandidate → 人工审核 → ApprovedMemory
岗位模板 + 个人配置 + 上下文 → RoleTwin
调用者 ActorContext ∩ RoleTwin能力边界 ∩ Tool权限 → 有效能力
有效能力 + CodexRuntime + ToolGateway → Web/飞书回答
回答 + 反馈 + 黄金集 → 自动回归与试点报告
```

## 任务组

- 知识：`KNO-001` 至 `KNO-008`。
- 记忆：`MEM-001` 至 `MEM-006`。
- 运行时：`AGT-002` 至 `AGT-008`。
- 分身：`TWI-001` 至 `TWI-007`。
- 渠道：`CHN-001` 至 `CHN-003`。
- 评测：`EVA-002` 至 `EVA-004`。
- 运维：`OPS-001` 至 `OPS-003`。
- 身份：`IAM-004` 至 `IAM-007` 中与授权、渠道映射和审计相关的任务。

## 首批资料

- 当前生效制度和KPI说明。
- 20至50个高频问题及管理者标准解释。
- 经人工选取的聊天记录样本，不批量导入全部历史。
- CEO角色职责、决策边界、偏好和回答示例。

## 验收演示

已绑定内部账号的员工在飞书询问制度问题，系统按员工权限选择可用证据并调用 CEO 分身回答；回答显示制度名称、版本、生效时间和原文定位。CEO 分身不能读取员工范围外资料。遇到无资料或无权限问题时使用不同的稳定结果并支持转人工。CEO 在管理台审核一条记忆候选后，新回答能够使用该记忆，但不覆盖现行制度。

## 退出条件

- 制度评测和角色评测达到 `docs/development/03-evaluation-strategy.md` 门槛。
- 至少一个真实部门完成试点。
- 有数据说明减少了多少重复咨询及新增了多少纠错工作。
- 跨部门、未知渠道身份和 RoleTwin 权限提升评测均为零越权。
